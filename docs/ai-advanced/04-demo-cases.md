# 04. 시세 진단 시연 케이스 — 아반떼·쏘렌토·그랜저 9건 + 한계 사례 1건

> 2026-09-03 작성. 판정 기준이 "적정가 ±5%"에서 **TabPFN 예측 분포 분위수 5단**으로 바뀐 직후(커밋 0d1a995),
> 시드가 가장 두터운 세 모델군의 판매중 매물 **146건 전부**를 배포된 것과 같은 엔진(`app/market_price.diagnose`)으로
> 돌려 고른 케이스다. 아래 수치는 전부 실측값이고, 스크린샷은 로컬 웹(운영 Supabase 로그인 + dev Cloud Run API)에서
> 상세 → [AI 시세 진단] → 채팅 카드 흐름을 그대로 찍은 것이다(`demo-shots/`).

## 0. 시연 전에 알아둘 것 (30초 설명용)

- **판정 5단**: 저렴(q10 아래) · 다소 저렴(q25 아래) · 적정(q25~q75) · 다소 높음(q90 이하) · 높음(q90 위).
  q10은 "모델이 보기에 이 차 가격이 그 값 **아래일 확률이 10%**"인 값. 폭은 사람이 정하지 않고 그 매물의 이웃 분포에서 나온다.
- **적정가** = 예측 분포의 평균(mean). 배지는 평균이 아니라 **분포 안의 위치**로 매긴다.
- **두 종류 근거가 같이 뜬다**: (a) SQL 비교군 통계(같은 세대·연료·사고 조건, 연식·주행 밴드 — 완화 사다리) → 중앙값·"하위 N%",
  (b) TabPFN 적정가·분위수. 둘이 **일치하면 강한 케이스**, **갈리면 "모델이 특징(주행·연식·사고)을 반영한다"를 보여주는 케이스**다.
- 학습표는 기본 모델군 전체(아반떼 53·쏘렌토 43·그랜저 47건). 모델은 차 이름을 모르고 연식·주행·배기량·연료·옵션수·무사고 10칸만 본다.
- ⚠️ **화면 숫자와 이 문서 숫자는 0.5% 안팎 다를 수 있다.** 문서의 적정가·분위수는 로컬 PC(api/.venv)에서, 스크린샷은 배포된 dev API
  (Cloud Run CPU)에서 계산한 값이다(예: A-2 적정가 로컬 1,502만 vs 화면 1,495만, G-2 2,099만 vs 2,103만). 두 환경 다 torch 2.13.0
  CPU판이지만 하드웨어(CPU 연산 경로)가 달라 부동소수 결과가 조금 갈리는 것으로 보이며, 원인은 컨테이너 안에서 직접 재현하지
  않아 확정하지 못했다. **판정 배지는 9건 모두 문서와 화면이 일치**했다. 시연 멘트에서는 만원 단위 끝자리를 읽지 말고
  "약 1,500만" 식으로 말한다.

### 전체 판정 분포 (2026-09-03 실측, 판매중 146건)

| 모델군 | 건수 | 저렴 | 다소 저렴 | 적정 | 다소 높음 | 높음 | 판정 없음 |
|---|---|---|---|---|---|---|---|
| 아반떼 | 54 | 4 | 12 | 22 | 10 | 5 | 1 (`아반떼MD`, DW-853) |

| 그랜저 | 48 | 5 | 9 | 22 | 10 | 2 | 0 |

적정이 절반 안팎, 양 끝(저렴·높음)이 각 10% 안팎 — 분위수 정의(q10/q90)와 맞는 분포다.

## 4. 한계 사례 (질문 받으면 이렇게 답한다)

### L-1. 아반떼 AD 2020 · 88,566km · 가솔린 · 무사고 · 옵션5 — 호가 **1,332만원 → 저렴** (스크린샷 없음, 의도적으로 시연 목록에서 뺌)

- 적정가 1,564만원(−14.8%)로 "저렴"이 떴지만, **의심스러운 판정**이다.
- 비교군(AD 세대 exact, 밴드 확대 5건)은 2017~2019년식 AD라 중앙값이 881만원, 이 차가 하위 100%(가장 비쌈). 통계와 모델이 정반대.
- 원인: 특징 벡터에 **세대(AD/CN7)가 없다.** 2020년은 AD(구형 마지막)와 CN7(신형 첫해)이 겹치는 해라, 모델은 이 2020년식 AD를
  학습표의 2020년식 CN7 이웃(1,451~1,579만원)과 같은 급으로 본다. 같은 2020년식 더 뉴 AD(7.8만km, 사고)가 1,308만원인 걸 보면
  1,332만원은 "저렴"이 아니라 대략 적정에 가깝다.
- 발생 조건: 세대 교체 연식에서만. 다른 연식은 연식 칸이 세대를 대신한다.
- 개선 방향(장부 DW-854): 학습표를 세대(정확 모델명)로 좁히거나 세대를 특징으로 추가. 단 좁히면 학습표가 16건으로 줄어 what-if가 죽는 문제(02 문서 후속 절)와 맞바꾸게 되므로 실측 후 결정.

## 5. 시연 순서 제안 (5분)

1. **G-3 → G-1** (그랜저 하이브리드 짝): 같은 모델군에서 ±5.7%가 각각 높음·저렴이 되는 걸로 "폭이 매물마다 다르다"를 보여준다.
2. **A-2**: 옛 ±5% 규칙이면 3만원 차이로 뒤집혔을 매물 → "다소 높음"이 왜 필요한지.
3. **S-2 또는 G-2**: 통계(하위 N%)와 모델 배지가 갈리는 케이스 → "중앙값은 주행거리를 모른다".
4. **A-1 / S-1**: 사고차인데 저렴 — "사고를 넣고도 싸다"로 가성비 매물 발굴 포인트.
5. 질문 받으면 **L-1**: 한계와 개선 방향까지 말하면 신뢰가 올라간다.

## 6. 재현 방법

- 판정 분포·후보 뽑기: `api/.venv`에서 `diagnose()`를 146건에 돌린 결과(세션 스크래치, 레포 밖). 같은 값은 배포된 dev API
  `GET /api/market-price/{id}`(로그인 필요)로 언제든 다시 받을 수 있다 — 응답의 `verdict`·`verdict_basis`·`tabpfn.quantiles`.
- 스크린샷: `web/`에서 `npm run dev -- --port 3000`(dev API의 CORS 허용 오리진이 3000뿐) → 로그인 → `/listings/{id}` → [AI 시세 진단].
