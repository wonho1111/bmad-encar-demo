# Story 18.1: 카카오 로그인

Status: ready-for-dev

## Story

As a 방문자,
I want 카카오 계정으로 바로 가입·로그인하고 싶다,
so that 이메일·비밀번호를 새로 만들지 않고 서비스를 쓸 수 있다.

범위: **웹만**(Epic 18 공통). Flutter 앱은 건드리지 않는다.

## Acceptance Criteria

1. **(카카오로 로그인 → 세션 + 홈)** `/login`(과 `/signup`)의 "카카오로 시작하기" 버튼 → 카카오 동의 화면 → 우리 사이트로 돌아와 세션이 생기고 홈 `/`에 로그인 상태로 도착한다.
2. **(첫 카카오 사용자도 프로필 생성)** 처음 들어온 카카오 사용자에게 `profiles` 행이 `role='user'`, `status='active'`로 생긴다. `name`이 비지 않는다 — 현재 트리거(`handle_new_user`, 0033)는 `split_part(new.email,'@',1)`로 이름을 만드는데 카카오가 이메일을 안 주면 `null`이 된다. 이메일이 없으면 카카오 닉네임(`raw_user_meta_data`)을 쓰도록 **새 마이그레이션으로 함수만 교체**한다(기존 행 UPDATE 금지, B3).
3. **(취소·실패 → 한국어 안내)** 카카오 동의 화면에서 취소하거나 콜백이 실패하면 `/login`으로 돌아와 한국어 오류가 보이고 세션은 없다. 원본 오류 메시지는 노출하지 않는다.
4. **(기존 이메일 계정과의 관계 실측)** 이미 이메일·비밀번호로 가입한 주소와 같은 이메일의 카카오 계정이 들어올 때 무슨 일이 생기는지(자동 연결 / 별도 계정 / 거부) **실제로 해보고** Dev Notes에 기록한다. 이 스토리에서 연결 정책을 새로 만들지는 않는다.
5. **(정지 회원은 카카오로도 못 쓴다)** `status='suspended'` 계정이 카카오로 로그인해도 기존 정지 차단(Epic 17)이 똑같이 걸린다.
6. **(비밀값은 저장소 밖)** 카카오 Client Secret은 환경변수로만. `supabase/config.toml`에는 `env(...)` 치환만 커밋한다.

## Dev Notes

- 현재 웹 인증: `web/src/app/(auth)/login`, `signup`, 헬퍼 `web/src/lib/supabase/{client,server,session,env}.ts`. OAuth 콜백 라우트는 아직 없다.
- 로컬 Supabase API 포트는 55321(`config.toml [api]`).
- `profiles.name`은 nullable(0009)이라 이메일 없는 카카오 사용자도 가입 자체는 실패하지 않지만 이름이 비게 된다 → AC2.
- **실측(2026-09-29)**: 새로 만든 카카오 앱의 동의항목에서 닉네임·프로필 사진은 바로 설정 가능, **카카오계정(이메일)·이름은 "권한 없음"**(설정 버튼 자체가 없음). 기본 앱으로는 이메일을 못 받는다.
