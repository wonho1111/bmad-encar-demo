## Intent

**Problem:** Flutter 앱은 아직 웹 개편(petrol/amber/신뢰그린 토큰, Pretendard) 이전의 임시 zinc/차콜 팔레트를 쓰고, 내비게이션은 Navigator 1.0 imperative push뿐이라 D12가 정한 하단 4탭(홈(AI)·찜·채팅·내차팔기) 구조가 없다. 또한 14.2가 깨뜨린 `currentRoleProvider` 계약(role 없는 세션에서 null)이 `app/test/`에 한 줄도 단언돼 있지 않고(DW-686), role 어휘의 정본이 DB 컬럼 주석에만 있고 `docs/conventions.md`엔 없다(DW-681).
**Approach:** `app_theme.dart`의 색 토큰을 웹 `DESIGN.md` 라이트 팔레트로 전면 교체(앱은 기존 결정대로 라이트 고정, 다크모드 없음)하고, `go_router`의 `StatefulShellRoute`(4브랜치, 탭 상태 보존) + Material 3 `NavigationBar`로 하단 탭 셸을 신설한다. 프로필은 우상단 아바타로 옮기고, `currentRoleProvider`의 role-없음 계약과 role 어휘 문서화를 이 스토리에 심는다(2026-08-07 인수조건 추가분, epics 문서).

## Boundaries & Constraints

**Always:**
- 색 토큰은 `DESIGN.md`/`globals.css`의 **라이트 모드 값만** hex 그대로 옮긴다(다크모드는 기존 결정대로 앱 범위 밖 — `app_theme.dart` 헤더 주석 "앱은 라이트 고정" 유지).
- 하단 4탭 = `GoRouter StatefulShellRoute`(브랜치별 `Navigator` 보존 → 탭 전환 시 스크롤·네비 스택 유지) + Material 3 `NavigationBar`. 탭: 홈(AI)·찜·채팅·내차팔기. **FAB 없음** — 기존 `floatingActionButtonTheme`(이미 죽은 코드, 어떤 화면도 `floatingActionButton`을 선언 안 함)을 제거한다.
- 라우터의 인증/관리자 분기는 현재 `AuthGate`(`main.dart:62-85`)와 **동일한 동작**을 유지한다: 미인증→로그인, `role==admin`→차단 안내(AR9), 그 외(role 없음 포함)→홈 셸. 메커니즘만 imperative→선언형으로 바뀐다.
- 프로필 접근은 우상단 아바타(현재 AppBar의 "로그아웃" 텍스트버튼 + 홈 본문 `_ProfileCard`를 대체) — 최소 이메일 표시 + 로그아웃 액션.
- 홈 최상단 AI 검색부(`_AiSearchCta`)는 petrol 그라데이션 배경 + amber 강조로 재도장한다(amber는 DESIGN.md 규칙대로 "핵심 CTA에만, 화면당 손에 꼽을 만큼" — 전역 버튼 기본색은 petrol이지 amber가 아니다).
- Pretendard는 **폰트 번들**(웹의 self-host woff2가 아니라 공식 OFL 배포의 TTF/OTF를 `app/fonts/`에 새로 받아 넣는다 — Flutter는 woff2를 폰트 에셋으로 못 쓴다) + `pubspec.yaml` `fonts:` 항목 + `ThemeData.fontFamily`. 타이포 스케일이 쓰는 굵기(500/600/700/800)만 넣는다.
- `docs/conventions.md`는 **끝에 새 `## 14.` 절만 추가**한다(기존 §1~13 번호는 절대 안 바꾼다 — 코드 곳곳의 `conventions.md §N` 주석 인용이 깨진다, 실측: `app/lib/features/listings/listing.dart` 등 5곳 이상이 번호를 인용).
- `app/test/`에 `currentRoleProvider`가 role 메타데이터 없는 세션에서 `null`을 반환함을 단언하는 위젯/유닛 테스트를 추가한다(DW-686) — `require_user_test.dart`의 `_fakeUser`+`ProviderScope(overrides:...)` 패턴을 재사용한다.

**Block If:**
- 공식 Pretendard 배포(OFL 라이선스, orioncactus/pretendard)에서 정적 TTF/OTF를 못 구하면(라이선스 불명 소스뿐이면) 임의 대체 폰트를 넣지 말고 HALT.
- 선택한 `go_router` 최신 안정판이 `StatefulShellRoute` 또는 이 프로젝트 SDK(`^3.12.2`)와 호환되지 않으면 HALT.

**Never:**
- 16.2(이미지·카드)·16.3(신뢰속성·찜 실제 기능)·16.4(실시간 채팅)·16.5(AI 4분기 응답)·16.7(사진 업로더)의 화면 로직을 구현하지 않는다 — 찜 탭은 **플레이스홀더**만("찜 목록은 곧 제공됩니다" 류), 실제 찜 토글·목록은 16.3 몫.
- 웹 히어로의 글로우/메시/차량 실루엣 아트를 재현하지 않는다 — petrol 그라데이션 + amber 강조까지만(데모 범위의 과잉 크래프트 방지, A2).
- `BackdropFilter`/blur 효과를 이번 스토리 신규 코드에 도입하지 않는다(구형 WebView no-op 우려 대상 자체를 안 만든다 — 불투명 표면만 사용).
- 홈 화면의 기존 퀵액션(문의 채팅·매물 등록·내 매물 관리)을 삭제하지 않는다 — 하단 탭과 일부 겹쳐도 유지(이번 스토리는 내비 셸 추가이지 홈 정보구조 재설계가 아니다).
- 앱 가입/역할 관련 로직(`auth_controller.dart`의 signUp, `user_role.dart`의 enum 값)을 바꾸지 않는다 — DW-686/DW-681은 **테스트·문서 추가**이지 계약 변경이 아니다.

### 2026-08-07 — 리뷰 세션이 자기가 쓴 인수조건의 자기모순을 정정 (2회차 리뷰 중)

바로 아래 루프백 항목에서 내가 추가한 인수조건 하나가 **같은 개정판의 Code Map과 어긋나 있었다**: AC는 "채팅 탭에서 방을 하나 연 뒤(**브랜치 안 push**) … 열어둔 방 화면이 그대로 보인다"를 요구했는데, Code Map은 채팅방을 "셸 밖 루트 Navigator로 보낼 상세류"에 넣었다. 둘 다 만족시킬 방법은 없다. intent-alignment 감사가 이 모순을 잡았고, 구현은 Code Map을 따르되 그 자리를 **합성 프로브 테스트**(브랜치 Navigator에 가짜 화면을 직접 push)로 메웠다 — 그건 이 앱이 아니라 `go_router`를 검사하는 것이라 어떤 앱 코드 변경으로도 red가 되지 않는다.

정정: 확정된 셸 경계(상세류 = 셸 밖)를 정본으로 두고, 매트릭스 4행은 **매트릭스가 지목한 채팅 탭의 스크롤 보존**으로 검증하도록 AC를 고쳤다. "네비 스택 보존"이 이 아키텍처에서 왜 관측 불가인지는 AC 본문과 테스트 파일 헤더 양쪽에 적었다. 합성 프로브 group은 제거했다.

**코드 재도출(bad_spec 루프백)은 하지 않았다** — 모순의 실제 코드 영향이 테스트 1개뿐이고, 재도출해도 같은 코드가 나온다. 대신 이 사실을 여기 남겨 다음 사람이 판단을 다시 볼 수 있게 한다.

## Design Notes

**셸 범위 결정 — 무엇이 하단 4탭 안에 살고 무엇이 밖으로 나가나(이 스토리가 빠뜨렸던 결정):**
`StatefulShellRoute.indexedStack`은 셸 `Scaffold`의 **body 안에** 브랜치별 `Navigator`를 만든다. 그래서 브랜치 안에서 `Navigator.of(context).push(...)`를 하면 그 화면은 셸 AppBar와 `NavigationBar` **아래에** 얹힌다 — 화면이 자기 AppBar를 갖고 있으면 AppBar가 2개가 되고, 셸 제목은 탭 이름("중고차 직거래")인 채로 남는다. 첫 구현이 정확히 이 상태였다(실측: 홈 → "문의 채팅" 진입 시 `AppBar=2`, `NavigationBar=1`, 제목 2개 공존).

**결정은 UX 산출물이 이미 갖고 있다** — 추가 판단이 필요 없다. 모바일 매물 상세 목업(`mockups/detail-1.html`)은 하단을 **가격+문의하기 스티키 바**가 차지하고 상단은 뒤로가기 `m-topnav`다. 하단 4탭 바가 없다. 반면 홈 목업(`mockups/app-home-2.html`)에는 4탭이 있다. 즉 **셸 = 탭 루트 4개의 껍데기**이고, 상세류는 셸 밖 전체화면이다.

따라서 상세류 진입은 **루트 Navigator**로 보낸다(`Navigator.of(context, rootNavigator: true)` 또는 `parentNavigatorKey: rootNavigatorKey`를 지정한 최상위 `GoRoute`). 대상은 AI 채팅·매물 탐색·매물 상세·채팅방·내 매물 관리·매물 수정, 그리고 홈 퀵액션이 여는 채팅목록·등록화면이다.

> ❌ **쓰지 않는 방식**: 화면에 `showAppBar` 같은 파라미터를 달아 셸 안에서 AppBar를 끄는 것. 첫 구현이 이 방식을 썼는데, 탭 루트 2곳만 고치고 **push 경로 8곳은 그대로 깨진 채 남았다.** 게다가 그걸 지키려고 쓴 테스트("AppBar 단일성")가 탭 루트만 검사해서 **101건 전부 초록인데 화면은 깨져 있는** 상태를 만들었다. 경계는 파라미터가 아니라 **어느 Navigator에 쌓느냐**로 긋는다.

**브랜치 영구 마운트 ↔ `autoDispose` provider 수명 충돌:** `IndexedStack`은 한 번 방문한 브랜치를 **계속 마운트한 채로 둔다**(그게 탭 상태 보존의 원리다). 그런데 이 앱엔 "화면이 닫히면 버린다"를 수명으로 삼는 `autoDispose` provider가 둘 있고, 그 화면들이 지금 탭 루트가 된다:
- `sellControllerProvider`(`sell_controller.dart:154`, 주석: *"등록 화면과 수정 화면이 같은 컨트롤러를 쓰더라도 서로의 입력/모드가 섞이지 않는다"*) — 무력화되면 **수정에서 새어나온 `editingId`가 등록 제출에 그대로 붙는다.** `submit()`이 `editingIdOverride ?? state.editingId`로 폴백하기 때문에(`sell_controller.dart:82`) 등록 버튼이 INSERT가 아니라 **기존 매물 UPDATE**를 친다. 실측 확인: 내차팔기 탭 미방문(대조군)이면 구독 종료 후 `editingId`가 `null`로 초기화되고, 탭을 한 번 방문한 뒤(실험군)엔 `listing-EDIT`가 그대로 남는다.
- `chatRoomsProvider`(`chat_providers.dart:16`, 주석: *"목록 화면을 닫으면 캐시를 버려 재진입 시 최신을 다시 읽는다"*) — 무력화되면 **채팅 탭을 다시 열어도 새 문의·읽지 않음 카운터가 갱신되지 않는다.** 실측: 첫 진입 조회 1회, 홈 갔다 재진입해도 여전히 1회.

**원칙: 수명(lifecycle)에 기대는 계약을 셸이 조용히 깨게 두지 않는다.** 고치는 방향은 provider 수명을 되살리는 게 아니라 **수명에 의존하지 않게** 만드는 쪽이다 — 등록/수정 모드는 호출부가 명시하고(폴백 제거), 목록 갱신은 탭 활성화 시 명시적으로 무효화한다. 앞으로 브랜치에 화면을 추가할 때마다 그 화면이 쓰는 `autoDispose` provider를 같은 눈으로 확인한다.

**색 토큰 분리 지침(옛 `ink`가 어디로 가는지):** 옛 `AppColors.ink`(#18181B)는 "본문 텍스트"와 "브랜드/버튼 강조색"을 한 상수로 뭉쳐 썼다(role 배지 배경에도, 텍스트에도 같은 값). 새 토큰셋은 이를 분리한다 — 순수 텍스트/아이콘 용도는 `inkPrimary`로, 버튼·내비·강조 용도는 `brandPetrol`로 옮긴다. 각 호출부(`AppColors.ink` 8곳)가 실제로 어느 역할이었는지는 파일별로 판단이 필요하므로 일괄 치환이 아니라 각 사이트를 보고 매핑한다. `muted`(11곳)는 대부분 `inkMuted`(meta·caption류)에 대응하되, 명백히 "보조 본문"인 자리는 `inkSecondary`를 쓴다. `border`(10곳)→`borderHairline`, `surfaceMuted`(2곳)→맥락에 따라 `surfaceRaised` 또는 `placeholderBg`.

**GoRouter 리액티비티 함정:** `GoRouter`의 `redirect` 콜백은 라우터 생성 시점에 한 번 평가되는 게 아니라 `refreshListenable`이 알려줄 때 재평가된다. `authStateProvider`(Riverpod `StreamProvider`)의 변화가 로그인/로그아웃 시 라우터를 실제로 다시 평가하게 하려면, 그 스트림을 구독해 `notifyListeners()`를 호출하는 `Listenable` 브리지(또는 `ref.listen` + 수동 `router.refresh()`)가 필요하다 — 이걸 빠뜨리면 로그인해도 로그인 화면에 멈춰 있는 흔한 실패 모드가 생긴다.

**"어차피 겹치는데 왜 퀵액션을 남기나":** 하단 탭이 생기면 홈의 "문의 채팅"·"매물 등록" 퀵액션과 목적지가 겹친다. 그래도 남기는 이유는 이 스토리가 **내비 셸 추가**이지 **홈 정보구조 재설계**가 아니기 때문이다(범위 최소화, A2) — 중복 제거는 16.6(통합 시연 검증)이나 후속 정리 스토리에서 실제 사용성 관찰 후 판단할 일.
