# Epic 11 Context: AI 히어로 랜딩 + 내비

<!-- Generated from planning artifacts. Regenerate with compile-epic-context if planning docs change. -->

## Goal

서비스의 첫 진입점을 AI 검색 히어로 랜딩으로 재구성한다: 딥 petrol 히어로 + 인기(view_count)/최신 2단 발췌 그리드 + 차종 빠른 진입 칩으로 "이게 어떤 서비스인지" 방문자가 즉시 체감하게 하고, 상단 내비를 개발용어가 아닌 소비자 자연어로 재구성한다. Epic 9/10에서 완성된 매물 카드를 그대로 재사용하며, 반응형 뷰포트(데스크톱/태블릿/모바일) E2E 감사를 이 에픽이 소유해 회귀를 배포 전에 잡는다.

## Stories

- Story 11.0: Pretendard self-host 전환 (기술부채 #40) — 히어로 첫인상의 폰트 FOUT/CLS 제거
- Story 11.1: view_count 스키마 + increment RPC 하드닝
- Story 11.2: 상단 내비 재구성
- Story 11.3: AI 히어로 랜딩 (히어로 + 차종 칩)
- Story 11.4: 인기/최신 매물 그리드
- Story 11.5: 반응형 뷰포트 E2E 감사 (SM-B)

## Requirements & Constraints

- 히어로 입력창은 로그인 여부와 무관하게 항상 활성 상태다(비활성화·자물쇠·사전 안내 금지 — 시도 전에 거절하지 않는다).
- AI 검색은 호출당 실제 비용(Gemini API)이 나가는 "행동"이라 로그인이 필수다. 다만 매물 열람(랜딩·목록·상세)은 비로그인도 허용된다 — 게이트는 행동에만 걸리고 열람에는 걸리지 않는다.
- 비로그인 사용자가 검색을 제출하거나 예시 칩을 클릭하면(칩=입력과 동일 취급) API를 호출하지 않고 로그인 게이트로 보낸다. 입력 문장은 보존했다가 로그인 복귀 시 입력창에 복원하되, 복원 후 자동 실행은 하지 않는다(사용자가 다시 눌러야 함 — 새로고침·뒤로가기로 인한 중복 과금 방지).
- "무료 검색 N번 남았어요" 류 잔여 횟수 카운터는 어디에도 표시하지 않는다.
- AI 검색 입력은 500자 상한 + 실시간 카운터로 초과를 막는다.
- sold(판매완료) 매물은 view_count 정렬·인기/최신 그리드에서 항상 제외된다(활성 강제지점 중 하나).
- 랜딩은 필터 상태·URL 쿼리파라미터를 소유하지 않는다 — 전체 목록·페이지네이션의 단일 소유자는 `/search`이며, 랜딩의 "전체 보기"는 거기로만 진입한다.
- 전역 내비에 "문의" 메뉴는 없다 — 문의는 매물 상세에서만 개시된다. 내비 라벨은 소비자 자연어("내 차 사기"·"AI로 찾기")를 쓰고 개발용어("탐색")를 쓰지 않는다.
- 반응형은 단일 코드베이스로 처리한다(m-dot 별도 사이트 아님). 그리드는 데스크톱 4열/태블릿 2열/모바일 1열로 재배치되며, 컴포넌트 내부 가로배치의 세로화·줄바꿈 어긋남·2줄 버튼이 없어야 한다(D5 반응형 무결성, 관리자 화면도 동일 규칙 적용 대상).

## Technical Decisions

- **view_count RPC 하드닝**: `listings.view_count int default 0` + `increment_listing_view(id)`는 SECURITY DEFINER로 만들되 `SET search_path=''` + `REVOKE EXECUTE FROM PUBLIC` + `GRANT EXECUTE TO anon, authenticated`를 적용한다. 추가로 `REVOKE UPDATE(view_count) FROM authenticated`(컬럼 단위 권한)로 직접 UPDATE 경로를 막아 이 RPC가 유일한 쓰기 통로가 되게 한다. 마이그레이션 번호는 착수 시 `supabase/migrations/` 실제 파일 목록에서 다음 빈 번호로 정한다(계획 문서의 번호는 이미 소진됨).
- 상세 페이지 진입 시 조회수가 +1 되며, AI 카드 렌더링 시에는 중복 증가하지 않는다(멱등 처리 필요).
- Client(웹)는 Supabase SDK + RLS로 view_count RPC·데이터에 직접 접근한다(FastAPI 경유 안 함, service_role 키 사용 금지 — 이 프로젝트 전역 원칙).
- 로그인 게이트 로직: 원 질의 문자열을 sessionStorage에 저장하고 `redirectedFrom`에 복귀 경로를 담아 로그인으로 보낸다. 로그인 성공 후 복귀 시 입력창에 복원하고, 복원 직후 sessionStorage 값은 즉시 제거한다(1회용 — 다음 방문에 옛 질문이 남지 않도록).
- 상단 내비는 role-aware 훅 자리로 선설계한다 — 이후 역할 분기(별도 워크스트림, 이번 에픽 범위 아님)가 붙을 때 내비 파일 전체를 재작성하지 않도록 구조를 미리 잡는다.
- 채팅 아이콘의 안읽음 배지 데이터·집계 로직은 이 에픽 범위가 아니다(후속 스토리 소유) — 11.2는 아이콘 자리만 배치하면 되고, 후행 기능 미완성에 의존하지 않는다.
- Pretendard는 `next/font/local`로 self-host 전환한다(가변 폰트, weight 축 `45 920`). 폰트는 CDN이 아니라 정적 서브셋 없이 전체를 내려받게 되므로(요청 수↓·페이로드↑ 트레이드오프) 실제 파일 용량을 재고 과하면 서브셋 생성을 검토한다. 기존 레이아웃의 `suppressHydrationWarning`·`min-h-full flex flex-col`·`h-full antialiased`는 그대로 유지한다.

## UX & Interaction Patterns

- 히어로 밴드: 딥 petrol 그라데이션(진한 petrol → 더 어두운 petrol) 배경 위에 은은한 글로우/메시 + 오른쪽 가장자리로 흐릿하게 흘러나가는 대형 차 실루엣 라인아트. 헤드라인 일부 음절만 amber로 강조. 흰 검색 pill + 우측 amber 검색 버튼(버튼 글자·아이콘은 항상 어두운 잉크색, 흰색 절대 금지 — 라이트/다크 공용 고정).
- 히어로 아래 상시 제안칩은 petrol 반투명 스타일. 대화/맥락 칩(되묻기 등, 다른 화면)은 탭 시 petrol 채움 "선택됨" 상태로 구분되는 별도 스타일 — 섞지 않는다.
- 상단 내비 구성: 로고 · 내 차 사기 · AI로 찾기 · 내 차 팔기 | 비로그인 시 로그인·내 차 등록 / 로그인 시 찜♡·채팅🔔·프로필▾(내 매물 관리·내 정보·로그아웃). 모바일 웹은 텍스트 링크가 햄버거로 접히고, 찜·채팅 아이콘은 상단에 항상 노출된다.
- 매물 카드는 Epic 9/10에서 확정된 레이아웃을 그대로 재사용한다(사진 5:3 → 신뢰속성 행 → 차량명 → meta → 가격 강조 → 희소옵션 칩, 찜 버튼은 사진 밖 우상단). 이 에픽에서 카드 디자인을 새로 만들지 않는다.
- reduced-motion 환경에서는 히어로 글로우·카드 호버 리프트 등 모션 효과를 축소/제거한다.
- 반응형 뷰포트 기준: 데스크톱 ≥1100px · 태블릿 640~1099px · 모바일 <640px.

## Cross-Story Dependencies

- 11.0(폰트 self-host)은 11.3(히어로) 이전에 완료돼야 한다 — 폰트 교체 증상(FOUT/CLS)이 가장 크게 보이는 화면이 히어로라서, 히어로를 만들기 전에 바닥을 깔아야 한다.
- 11.1(view_count 스키마·RPC)은 11.4(인기/최신 그리드)의 선행 조건이다 — "인기" 정렬이 view_count에 의존한다.
- 11.3·11.4는 Epic 9/10에서 완성된 매물 카드 컴포넌트를 전제로 한다(신규 제작 아님, 재사용).
- 11.2의 채팅🔔 안읽음 배지는 아이콘 자리만 배치하며, 실제 배지 데이터·집계는 Epic 12(Story 12.5)가 소유한다 — 11.2는 그 완성을 기다리지 않는다.
- 11.5는 랜딩·목록·상세·카드 화면이 모두 갖춰진 뒤에 도는 통합 감사이며, 대장(열린 일 장부)에서 이월된 두 항목을 함께 닫는다: (1) 이미지 요청 실패 시 폴백을 목록/상세/AI 세 소비처 각각에서 재현(단, `loading="lazy"`로 화면 밖 카드는 요청 자체가 안 나가므로 스크롤로 전량을 뷰포트에 넣거나 lazy를 꺼서 검증해야 함), (2) 검증에 쓴 스크린샷·네트워크 로그를 재실행 가능한 형태로 레포에 남긴다(기존엔 `.gitignore` 대상이라 남지 않았음).
