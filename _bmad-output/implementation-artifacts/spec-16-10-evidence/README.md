# spec-16-10 육안 확인 증거 (2026-08-10, 이 세션)

spec-16-10이 요구한 실기기 육안 확인 — 히어로·검색창 마감 4축 + 카드 radius를 눈으로 대조한다.

기기: mobile MCP 연결 `SM-G991N`(id `192.168.219.103:36959`, `platform: android`,
`type: emulator`, `state: online` — 기기 리스트가 emulator로 보고하므로 "물리 기기"로
과장하지 않는다). `.env.json.prod`(prod 백엔드)로 빌드한 debug APK, 로그인 상태(prod 시드
판매자 매물이 그대로 노출).

| 파일 | 확인한 축 | 결과 |
|---|---|---|
| `01-hero-headline-eyebrow-search.png` | ①헤드라인 36px·2줄 ②eyebrow "AI 매물 검색" ③검색창 테두리(**비포커스 상태만**) ④차 실루엣 ⑤히어로 밴드 하단 곡률 | ✅ 헤드라인이 "원하는 차를"/"말로 찾으세요" 2줄로 눈에 띄게 크다(예전 19px 대비 확연) · eyebrow 라벨(점+텍스트)이 헤드라인 위에 pill로 보임 · 검색창은 흰 배경에 테두리 없이 깔끔함 · 우상단에 차 실루엣이 은은하게 걸쳐 보임(지붕선 + 바퀴 원 2개 — 목업 규칙 `top:-14%` 때문에 차체 대부분이 밴드 위로 잘려 나간다) · 히어로 밴드 하단 곡률이 완만하다 |
| `02-card-radius-16.png` | 카드 radius | ✅ 매물 카드 모서리(사진 상단 포함)가 카드 radius(16)로 둥글다 |

**이 촬영이 보지 못한 것**(추측이 아니라 조건상 불가):
- 검색창 **포커스 상태**(키보드 표시)는 자동화 탭 타이밍상 캡처하지 못했다. 그래서 이 표의
  "테두리 없음"은 **비포커스 상태에 대한 관찰일 뿐**이다 — 포커스 상태의 유효 테두리는
  위젯 테스트(`home_ai_entry_test.dart` "activation·focus 상태 모두 유효
  enabledBorder/focusedBorder가 InputBorder.none이다")가 대신 단언한다.
- **변경 전(before) 화면은 남기지 못했다.** 그래서 "예전보다 곡률이 완만해졌다" 같은 비교는
  이 파일들로 증명되지 않는다 — 22→16이라는 값 변화는 코드와 위젯 테스트가 증명하고,
  이 스크린샷이 증명하는 건 "지금 화면이 이렇게 보인다"까지다.
- 다크모드·태블릿 폭·긴 차량명 오버플로는 이 촬영 범위 밖이다(앱은 라이트 고정이라 다크모드는
  애초에 범위 밖).

## 웹 390px·1440px 육안 대조 (2026-08-10 코드리뷰 2패스에서 실제 수행)

구현 단계에서 브라우저 프로필 락(`Browser is already in use`)으로 못 했던 대조를, 2패스가
`web/node_modules`의 playwright를 **독립 프로세스**로 띄워(MCP 프로필을 안 건드리므로 락과 무관)
로컬 `npm run dev`에 붙여 실제로 수행했다.

| 파일 | 무엇 |
|---|---|
| `03-web-390-before.png` / `03-web-390-after.png` | 폰 폭(390×844) 히어로 |
| `04-web-1440-before.png` / `04-web-1440-after.png` | 데스크톱(1440×900) 히어로 |

**before = 앱 배치 규칙(`-top-[14%] w-[56%]`)을 웹에 그대로 복사한 상태.** 브라우저에서 잰 수치:

| 뷰포트 | 그려지는 잉크 높이 | 그중 실제로 보이는 양 | svg 폭 |
|---|---|---|---|
| 390px (before) | 60.4px | **15.3px (25%)** — 바퀴 밑동만 | 218px |
| 390px (after) | 62.6px | 36.0px (57%) | 226px |
| 1440px (before) | 223px | 223px | **806px (목업 상한 640 초과)** |
| 1440px (after) | 177px | 153px (87%) | 640px (상한 적용) |

`top`의 퍼센트는 컨테이너 **높이** 기준인데, 목업의 앱 프레임은 220px 고정 밴드인 반면 웹
`<section>`은 높이가 콘텐츠에 따라 유동적이다(390px에서 실측 431.6px) — 그래서 같은 `-14%`가
웹에서는 훨씬 큰 픽셀 값이 되어 차를 화면 밖으로 밀어낸다. after는 목업이 **웹 프레임용으로 따로
정해 둔** 규칙(`consistency-1.html:170` `.silhouette` = `right:-4%; bottom:-6%;
width:min(58%,640px); opacity:.10`)을 적용한 결과다.

**2026-08-10 코드리뷰 2패스 정정**: 원래 이 표는 `02-card-radius-16.png`에 "히어로 밴드 하단
곡률이 예전(22)보다 완만해 보임"을 배정했는데, 02는 스크롤된 화면이라 **히어로 밴드가 아예
보이지 않는다**(리뷰 세션이 두 파일을 직접 열어 확인). 곡률이 실제로 보이는 건 01이므로 그쪽으로
옮겼고, before 이미지 없이 하던 "예전보다" 비교는 지웠다(CLAUDE.md B4 — 재보기 전엔 선언하지
않는다).
