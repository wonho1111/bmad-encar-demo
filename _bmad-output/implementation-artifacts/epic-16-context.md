## Goal

웹이 이번 증분(이미지·카드·신뢰속성·찜·실시간 채팅·4분기 AI·랜딩)으로 먼저 개편된 뒤, Flutter 앱을 같은 디자인 언어와 기능으로 미러링한다. 웹 셸을 재사용할 수 없어 앱은 별도 위젯으로 구현하되, 색·타이포·카드 구성·API 계약은 웹과 공유해 "웹에서 앱으로 와도 같은 서비스"로 느끼게 한다. 웹 안정화 이후 착수하는 후행 에픽이다. ✎ 착수 시점 범위(토큰·내비·이미지·신뢰속성·찜·채팅·AI)에 더해, 웹에는 있는데 애초 계획에서 앱 짝이 빠져 있던 화면 2개(16.7 사진 업로더, 16.8 홈 랜딩)가 사용자 결정으로 추가됐고, 8개 스토리를 실물로 반영한 뒤 실기기 화면이 목업·시각 스파인과 눈에 띄게 다르다는 사용자 지적이 나와 교정 스토리(16.9)가 더해져 지금은 **9개 스토리**가 범위다. 16.9는 새 기능이 아니라 이미 만든 화면(주로 홈 최상단·매물 카드·상세 CTA)을 확정된 스파인대로 다시 맞추는 정합성 작업이다.

## Requirements & Constraints

- FR39: 앱을 웹과 동일 디자인 언어(색 토큰·카드 구성·신뢰속성/옵션 표시·플레이스홀더 규칙)로 개편.

DW-738에 실제로 남은 것은 원인 미해결이 아니라 **수정 이후의 실기기 재확인**이다(등재: DW-763).

## Technical Decisions

- **이미지 URL = 공개 버킷 + 고정 URL, 서명 URL 아니다.** ADR-IMG-02가 비공개+서명 방식을 대체(`getPublicUrl(bucket, path)`로 조립, 만료 없음). api는 `storage_path`만 반환, URL은 web/app이 각자 조립한다.
- **실시간 채팅 = Supabase Realtime "Broadcast from Database".** 토픽 `chat:room:{room_id}`을 트리거·RLS·클라 구독 3곳이 동일하게 써야 한다. 갭보정 = Broadcast Replay(≤25건/72h) 우선 → 초과분은 `created_at >=` 커서 재조회 + `client_message_id` dedup. Flutter는 `supabase_flutter` Realtime으로 동일 계약.
- **AI 응답 계약**: `{answer, listings[], route: REJECT|CLARIFY|SQL|HYBRID, narrowed_by?, clarify?: {question, chips}}`. answer는 결정론 생성(LLM 자유 재작성 금지).
- **하단 내비 = `GoRouter StatefulShellRoute`(탭 상태 보존) + Material 3 `NavigationBar`.** 4탭: 홈(AI)·찜·채팅·내차팔기, FAB 없음. 프로필=우상단 아바타. **"내 차 사기"는 전용 탭이 아니라 홈 하단 스크롤/필터로 도달한다**(탭을 늘리지 않는다).
- 디자인 토큰은 웹 단일 출처를 미러링(색·타이포·카드 레이아웃 B·초록 신뢰뱃지·amber는 가격/CTA 전용·딥 petrol 히어로는 라이트/다크 동일). 폰트는 Pretendard를 앱에 번들. 구형 WebView는 `backdrop-filter` blur가 no-op → 불투명 배경 폴백.
- 역할 어휘: `profiles.role`은 `admin`만 특별 취급, 그 외 전부 `user`. 접근 권한은 이 값이 아니라 소유권(`seller_id`)+RLS로 판정.
- 신뢰속성(`accident_status` 텍스트+CHECK, `is_single_owner`, `is_non_smoker`)은 전부 nullable, NULL="미입력" 제3상태, 항상 "판매자 제공 정보" 면책과 한 몸. 찜은 DB 단일 저장(`wishlists`), 웹·앱 간 실시간 동기화 없음.
- **16.9 — 홈 최상단(상태바~앱바~히어로) 시각 규정**: 상태바·앱바·AI 히어로가 색 경계 없이 하나의 딥 petrol 면으로 이어진다(흰 앱바 + 여백 있는 카드형 히어로였던 것을 교정). 앱바 좌측은 로고 lockup(petrol 라운드-스퀘어 배지 + "차" + "차장님" 워드마크), 우측은 아바타 하나만(알림 벨 없음 — 스파인·EXPERIENCE 어디에도 없고 누를 곳도 없음). 히어로 배경에 글로우/메시(petrol·amber 빛무리)와 대형 차 실루엣 라인아트(우상단, 옅게, 칩·검색창 비침범)가 들어간다 — 스파인이 "허전함 해소 + 자동차 정체성" 목적으로 명시한 요소.
- **16.9 — 히어로 하단 정리**: 히어로 바로 아래 "어떤 차를 찾고 있나요?" 탐색 진입 박스를 제거해 히어로 다음이 바로 차종 칩이 되게 한다. 이 제거는 히어로 교정과 같은 커밋이어야 한다(먼저 지우면 중간 상태가 커밋으로 남는다). 차종 칩의 "전체"는 선택 상태(petrol 채움)로 보인다 — 앱 목업 기준이며 웹에는 이 선택 상태가 없지만 이 스토리는 앱만 손댄다.
- **16.9 — 매물 카드 계약(`ListingCard.tsx`·`card-final-1.html`·스파인 §매물 카드가 정본)**: ① 가격이 카드에서 시각적으로 가장 큰 요소(26/800 상당) + 가격 전용 강조 토큰(`price-emphasis`)로 표시 — 차량명과 같은 무게의 검정 텍스트이면 오답. ② 희소옵션 칩(petrol 아웃라인 3~4개, 넘치면 "외 N")은 옵션이 없어도 슬롯을 예약해 카드 높이가 흔들리지 않게 한다. ③ 신뢰속성 행은 사진 위 오버레이가 아니라 사진 바로 아래 전용 행(초록 칩 + 면책 muted 11px). ④ 정보 순서 = 사진 → 신뢰속성 → 차량명 → meta(주행·연료·지역·판매자) → 가격 → 옵션 칩. **카드 크기·열 수는 바꾸지 않는다**(D5가 4→2→1 열 축소를 규정, 브레이크포인트 1100/640px에서 390px는 1열이 맞다 — `ai-flow-1.html`의 2열 모바일 프레임은 목업 변형이라 따르지 않는다).
- **16.9 — 매물 상세**: 하단 고정 바(판매가 + 문의하기)를 추가한다(`detail-1.html` 모바일 프레임 + 스파인 "sticky 문의 바"). 지금은 없어서 스크롤 중 CTA를 놓친다.
- **16.9 — 검사 방식**: 위 항목마다 위젯 테스트로 시각 축을 직접 단언한다 — 앱바·히어로 배경색 연속 여부, 히어로 좌우 여백 0(화면 폭 꽉 참), 히어로 다음 위젯이 차종 칩인지(탐색 박스 0개), 카드 가격 글자 크기 > 차량명 글자 크기, 옵션 칩 슬롯이 옵션 0개일 때도 존재하는지, 신뢰속성이 사진 위젯 뒤(아래)에 오는지. 채택 전 일부러 깨서 red를 확인해야 한다(기존 검사가 이 갭을 놓친 이유가 순서·개수만 봤기 때문이므로, 새 검사도 같은 함정에 빠지지 않았는지 스스로 증명).

## UX & Interaction Patterns

- 히어로 밴드: 딥 petrol 그라데이션, "원하는 차를 **말**로 찾으세요"(말만 amber 강조) + 알약형 입력 + amber 검색 버튼. 제안 칩 4개는 웹 `HeroSearch.tsx`의 `SUGGESTIONS`가 정본(가성비 좋은 첫차·4천만원대 전기 SUV·주행거리 짧은 무사고 세단·7인승 디젤 패밀리카).
- 차종 칩: 전체·경차·SUV·전기·화물·승합("세단"·"수입"은 DB 값에 대응이 없어 웹이 이미 대체). 탭하면 해당 필터로 이동. 16.9 적용 후 "전체"는 기본 선택(petrol 채움) 상태로 보인다.
- "지금 인기"(view_count desc)·"방금 올라온 매물"(created_at desc) 2섹션, 각 4건 + 전체보기. 앱은 웹의 가로 2단이 아니라 세로 2섹션.
- Epic 7 잔재 퀵액션(문의 채팅·매물 등록·내 매물 관리 3버튼)은 히어로/칩/2섹션 신설과 같은 커밋에서 제거 — 먼저 지우면 하단 탭이 그 화면을 아직 못 여는 동안 판매자가 등록 경로를 잃는다.
- 매물 카드(레이아웃 B, 16.2가 만들고 16.9가 시각 규정을 재확인): 사진 5:3 커버(우하단 "N장" 배지, 없으면 "사진 준비중") → 신뢰속성 행 → 차량명 → meta → 가격(최상위 강조) → 희소옵션 칩. 찜(♡)은 사진 밖 우상단 원형 버튼. 상세는 스와이프 갤러리 + "1/N" 카운터 + 16.9가 추가하는 하단 고정 바(가격+문의하기).
- 사진 업로드는 OS 갤러리/카메라 네이티브 피커(크롭·회전·동영상은 범위밖), 업로드 전 클라이언트 리사이즈/압축.
- 매물 상세 진입 시 `increment_listing_view` RPC 호출(웹과 같은 호출 지점 단일성 검사로 이중 호출 방지) — 16.6에서 완료 처리됨.

## Cross-Story Dependencies

- **실행 순서(정본=sprint-status.yaml)는 문서 번호와 다르다**: 16.1→16.2→16.3→16.4→16.5→16.8→16.7→16.6→**16.9**. 16.6(실폰 통합 검증)은 16.8·16.7이 만드는 화면이 있어야 검증이 성립하므로 그 다음에 돈다 — **완료 기준은 "배선했다"가 아니라 실폰에서 실제로 동작하는 것이다: 상세 열람 전/후로 "지금 인기" 순서가 실제로 바뀌는 것, 로그아웃 상태로 홈·목록·상세에 도달하고 찜/문의를 누를 때만 로그인으로 유도되는 것까지 확인해야 완료다(존재 확인 ≠ 작동 확인).** 16.9는 16.1~16.8이 이미 실물로 반영한 화면(특히 16.1의 앱바·내비, 16.8의 홈 히어로/칩/섹션, 16.2의 매물 카드)을 스파인 기준으로 다시 대조·교정하는 마무리 단계라 그 전 스토리들 뒤에 온다. 회고(epic-16-retrospective)보다 먼저 실행된다.
- 16.9는 **네 항목(앱바·히어로 연속면 DW-759, 히어로 배경 요소·탐색박스 제거 DW-755, 카드 정합 DW-760, 상세 sticky 바 DW-735)이 전부 홈 화면 최상단 한 덩어리**라 따로 고치면 중간 상태가 어색해지므로 한 스토리로 묶여 있다 — 부분 구현하지 않는다.
- 16.8은 웹 Epic 11 랜딩(`HeroSearch`·`CategoryChips`·`PopularRecentGrid`)과 확정 목업 `app-home-2.html`을 따르는 미러 작업. 16.9는 그 결과물 중 시각 스파인과 어긋난 부분만 교정하는 것이지 16.8의 정보구조를 다시 설계하지 않는다.
- 16.7은 웹 Story 9.3이 확정한 업로드 계약(정본 `docs/conventions.md` §10.1)을 그대로 준수.
- 16.1~16.5는 각각 웹 Epic 9(이미지)·10(신뢰속성·찜)·12(실시간 채팅)·13(AI 4분기)이 이미 안정화한 기능을 앱에 옮기는 작업으로, 해당 웹 기능이 선행 조건이다.
