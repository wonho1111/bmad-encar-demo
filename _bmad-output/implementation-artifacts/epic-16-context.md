## Goal

웹이 이미 개편한 디자인 언어와 화면(이미지·카드 재설계·신뢰속성·찜·실시간 채팅·4분기 AI·AI 히어로 홈)을 Flutter 앱에 미러링한다. 웹 셸(React 컴포넌트)은 재사용할 수 없어 앱은 별도 위젯으로 새로 구현하되, 색·비율·필드 등 계약은 `docs/conventions.md`를 단일 출처로 공유한다. 착수 시점 범위(토큰·내비·이미지·신뢰속성·찜·채팅·AI)에 더해, 웹에는 있는데 애초 계획에서 앱 짝이 빠져 있던 화면 2개(사진 업로더, 홈 랜딩)가 사용자 결정으로 추가되어 지금은 8개 스토리 전체가 이 에픽의 범위다. 앱 단계에서는 웹의 UX/아키텍처 결정을 다시 논의하지 않고 플랫폼 셸 표현만 번역한다.

## Stories

- Story 16.1: 디자인 토큰 미러 + 하단 4탭 내비
- Story 16.2: 이미지·카드 재설계 (앱)
- Story 16.3: 신뢰속성·찜 (앱)
- Story 16.4: 실시간 채팅 (앱)
- Story 16.5: 4분기 AI 응답·되묻기 칩 (앱)
- Story 16.6: SM-D 통합 시연 검증 (앱)
- Story 16.7: 앱 사진 업로더
- Story 16.8: 앱 홈 랜딩 미러

## Requirements & Constraints

- 앱 화면은 웹과 동일한 디자인 언어(색 토큰·카드 구성·신뢰속성/옵션 표시·플레이스홀더 규칙)로 개편해야 한다.
- 문의 채팅은 폴링이 아니라 실시간(구독)이어야 하며, 메시지가 상대에게 즉시 반영된다. 클라 생성 멱등키로 재전송 중복을 막고, 연결 끊김은 비차단 배너로 알리며, 재연결 시 "마지막 수신 이후" 보정 조회로 갭을 메운다.
- 로그인 사용자는 매물을 찜(토글)할 수 있고 찜 목록에 도달할 수 있다. 채팅 진입점에는 안 읽은 메시지 카운트 배지, 방 목록은 최신 문의 순.
- 비로그인 사용자도 매물 열람(목록·상세·홈)은 가능하다. 로그인 게이트는 "행동"에만 건다 — 상태를 바꾸거나 과금이 발생하는 행동(AI 검색·문의·매물 등록·찜)만 게이트하고 단순 열람은 게이트하지 않는다. ✎ 정정 2026-08-08: 이 요구사항은 현재 **웹에서만** 성립한다 — 앱은 `app_router.dart`의 `redirect`가 미인증 사용자를 모든 경로에서 `/login`으로 보내 비로그인 열람 자체가 없다(실측: `user == null`이면 auth 경로 제외 전부 `/login`). 이 모순은 DW-738에 등재돼 있고, 앱도 열지 웹 한정으로 문서를 좁힐지는 아직 미결정이다(Epic 16-6 착수 시 결론).
- 사진 업로더는 웹이 이미 확정한 경로 규약·저장 규격을 그대로 따라야 한다. 업로드 실패로 Storage에 고아 파일을 남기지 않아야 하고(결정론적 파일명으로 재시도가 덮어쓰기), 삭제는 Storage 오브젝트 삭제 후 DB 행 삭제 순서를 지켜야 한다. sold 매물은 사진 추가·삭제가 DB 정책으로 막혀야 한다.
- 앱 홈은 웹 랜딩과 동일한 정보구조(히어로 검색 + 차종 칩 + 인기/최신 매물 섹션)여야 하며, 인기/최신의 정렬·발췌 건수(각 4건)는 웹과 동일해야 한다 — 색상만이 아니라 레이아웃·정보구조 전체가 대상이다.
- 앱은 웹과 동일 디자인 언어의 별도 구현이며, 반응형 웹처럼 하나의 코드베이스를 공유하지 않는다.
- Non-goals(에픽 전체): 브라우저/모바일 푸시, 안드로이드 릴리스 서명, 관리자 화면의 앱 이월. Non-goals(16.8): 웹 랜딩 재작업, 판매자 화면(매물 등록·내 매물 관리) 리스킨, 색 토큰 작업(이미 별도로 종결).

## Technical Decisions

- 시각 토큰의 원본은 웹 DESIGN.md(petrol=신뢰/구조, amber=가격·CTA 전용, 신뢰속성=별도 초록 계열)이며 계약 형태로 `docs/conventions.md`에 이월된다. amber CTA의 글자·아이콘은 항상 어두운 잉크로 고정. Pretendard 폰트는 웹은 CDN(self-host 전환 완료), 앱은 폰트 번들.
- 내비게이션 = `GoRouter StatefulShellRoute`(탭 상태 보존) + Material 3 `NavigationBar`. 하단 4탭: 홈(AI검색)·찜·채팅·내차팔기, FAB 없음. 프로필은 우상단 아바타. AI는 별도 탭이 아니라 홈 최상단 큰 검색부(웹 히어로의 앱 번역판). "내 차 사기"(전체 매물)는 별도 탭 없이 홈 하단 스크롤(인기·최신)·필터에서 도달한다.
- backdrop-filter blur는 구형 Flutter WebView에서 no-op이므로 불투명 폴백을 쓴다.
- 이미지 URL 계약(현재 정본, `docs/conventions.md` 단일 출처): 이미지 버킷은 **공개** 버킷이고 URL은 만료 없는 고정 URL(`getPublicUrl(bucket, path)`로 경로에서 조립)이다 — 서명·발급 왕복 없음. web·app 양쪽이 이 헬퍼를 미러링해서 쓴다(app은 `core/supabase/storage_helper.dart`). api(FastAPI)는 URL을 만들지 않고 `storage_path`만 반환한다(`ai_readonly` 최소권한). URL 존재가 파일 존재를 보장하지 않으므로 소비처가 로드 실패 시 "사진 준비중" 플레이스홀더로 폴백해야 한다.
- 실시간 채팅 전송 = "Broadcast from Database"(DB 트리거 → `realtime.messages` private 채널) — `chat_messages` 테이블이 소스 오브 트루스이고 정렬은 클라가 `created_at` 기준으로 한다(Broadcast 전달 순서는 보장되지 않음). 토픽 이름 `chat:room:{room_id}`은 web/app/DB 3곳이 동일해야 한다. Flutter는 `supabase_flutter` Realtime 구독으로 웹과 같은 계약을 그대로 쓴다.
- AI 검색 상태(Riverpod)는 웹과 동일한 형태로 미러링한다 — 응답은 구조형/하이브리드/되묻기/거절 4갈래이며, api가 라우팅과 되묻기 사유를 구조화해 내려준다. 되묻기 턴 상한(2~3턴)은 서버가 강제하고, 클라는 별도 카운터를 두지 않는다(`clarify`가 null로 오면 칩을 안 그리는 것 자체가 반영).
- `accident_status`는 텍스트+CHECK 제약: 무사고=초록 신뢰뱃지, 단순교환/사고=가치중립 중립칩. 셋 다 "판매자 제공 정보" 면책이 붙는다. 옵션은 통제 어휘 + 희소도 매핑을 쓴다(카드는 상위 3~4개, 상세는 카테고리 전량).
- 앱 홈 랜딩의 구조는 새로 디자인하지 않는다 — 웹 구현(Epic 11의 히어로 검색·차종 칩·인기/최신 그리드)과 확정 목업이 정본이며, 앱은 세로 스크롤 배치(웹의 가로 2단 대신 인기/최신을 세로 2섹션으로 쌓음)로만 번역한다.
- Client ↔ Supabase 직접 연동(SDK+RLS)이 원칙이다: 이미지 Storage·Realtime 채팅·찜은 FastAPI를 경유하지 않는다. FastAPI는 AI 검색 전용 경계다.

## UX & Interaction Patterns

- 매물 카드(레이아웃 B): 사진 5:3 → 신뢰속성 전용 행(초록 칩+면책) → 차량명 → meta(주행/연료/지역, muted) → 가격 최상위 강조 → 희소옵션 아웃라인 칩. 찜(♡)은 사진 밖 우상단 원형 버튼, "N장" 배지는 사진 위 우하단 다크 글래스 pill.
- 상세 사진 갤러리는 스와이프 + "1/N" 카운터(웹은 좌우 화살표).
- 되묻기 칩은 탭 가능하고 선택 시 petrol 채움 상태가 되며, 자유 타이핑과 병존한다. AI 입력은 최대 500자.
- 뒤로가기는 기본적으로 진입한 화면으로 복귀하되, 파괴적 액션 후에는 안전한 목록으로 명시 이동한다. 앱은 OS 시스템 뒤로가기 제스처로 이 규칙을 구현한다.
- 채팅 메시지 버블: 내 메시지=petrol 채움·우측 정렬, 상대=surface-raised·좌측 정렬. 읽음 표시·타임스탬프·전송중(pending) 반투명 상태.
- 사진 업로드는 OS 갤러리/카메라 **네이티브 피커**로 진입한다(웹의 드롭존 UI 이월 없음).
- 홈 랜딩: 딥 petrol 히어로 밴드 — 큰 타이포("원하는 차를 **말**로 찾으세요", '말'만 amber 강조) + 알약형 입력 + amber 검색 버튼 + 제안 칩(가성비 좋은 첫차·전기 SUV·무사고 세단 ✎ 정정 2026-08-08: **가성비 좋은 첫차·4천만원대 전기 SUV·주행거리 짧은 무사고 세단·7인승 디젤 패밀리카**(웹 HeroSearch.tsx의 SUGGESTIONS 4개 — 이 목업 3개 대신 웹이 이미 안정 운영 중인 정본을 따름)). 히어로 아래 차종 칩 줄(전체·경차·세단·SUV·전기·수입 ✎ 정정 2026-08-08: **전체·경차·SUV·전기·화물·승합** — DB `body_type`/`fuel`에 "세단"·"수입" 1:1 대응 값이 없고, 웹이 이미 같은 이유로 화물·승합으로 대체해 둔 걸 앱도 그대로 따른다. 사용자 결정 2026-08-08) — 탭하면 필터 탐색으로 이동. 그 아래 "지금 인기"(view_count 내림차순)·"최신"(created_at 내림차순) 2섹션이 각각 4건 발췌 + 전체보기 진입으로 세로로 쌓인다.

## Cross-Story Dependencies

- 16.1(토큰·내비 셸)이 기반이며, 16.2~16.5·16.7·16.8의 화면이 그 위에서 렌더된다.
- 16.2(이미지 카드)·16.3(신뢰속성·찜)은 웹/앱/api가 락스텝으로 공유하는 ListingCard 계약(Epic 9·10에서 확정)을 그대로 소비한다 — 재정의하지 않는다.
- 16.4(채팅)는 Epic 12에서 구축된 Realtime Broadcast·멱등키·`chat_room_reads` 인프라를 그대로 구독한다.
- 16.5(AI)는 Epic 13에서 확정된 `/ai/search` 4분기 응답 계약을 그대로 소비한다.
- 16.7(사진 업로더)은 웹 Story 9.3이 확정한 경로 규약·저장 규격·삭제 순서를 그대로 따른다.
- 16.8(홈 랜딩)은 Epic 11(웹 AI 히어로 랜딩)의 컴포넌트 구조·정렬·발췌 건수를 정본으로 삼아 앱에 번역하는 자리이며, 새 설계가 필요 없다. 다만 홈 개편과 **같은 커밋**에서 Epic 7 잔재 퀵액션 3개(문의 채팅·매물 등록·내 매물 관리 바로가기)를 제거해야 한다 — 그 전에 먼저 지우면 하단 4탭(16.1)이 같은 진입점을 이미 대체하고 있는지 확인되지 않은 채로 판매자가 매물 등록에 갈 길이 끊길 수 있다.
- 16.6(SM-D 통합 시연 검증)은 스토리 번호상 6번이지만 **실제 실행 순서는 16.8 → 16.7 → 16.6으로 맨 마지막에 돈다** — 이 스토리가 검증하는 대상 화면(16.8의 홈, 16.7의 사진 업로더)이 아직 없는 상태로 돌면 검증이 성립하지 않기 때문이다. 검증 범위도 16.1~16.5뿐 아니라 16.7·16.8을 포함하도록 확장되어 있다.
