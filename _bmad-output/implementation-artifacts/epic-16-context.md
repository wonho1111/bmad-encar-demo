## Goal

웹이 이번 증분(이미지·카드·신뢰속성·찜·실시간 채팅·4분기 AI·랜딩)으로 먼저 개편된 뒤, Flutter 앱을 같은 디자인 언어와 기능으로 미러링한다. 웹 셸을 재사용할 수 없어 앱은 별도 위젯으로 구현하되, 색·타이포·카드 구성·API 계약은 웹과 공유해 "웹에서 앱으로 와도 같은 서비스"로 느끼게 한다. 웹 안정화 이후 착수하는 후행 에픽이다. 착수 시점 범위(토큰·내비·이미지·신뢰속성·찜·채팅·AI)에 더해, 애초 계획에서 앱 짝이 빠졌던 화면 2개(16.7 사진 업로더, 16.8 홈 랜딩)가 추가됐고, 실물 반영 뒤 실기기 화면이 목업·시각 스파인과 다르다는 사용자 지적으로 교정 스토리 2건(16.9=레이아웃·구조·색, 16.10=타이포·질감·마감)이 더해져 지금은 **10개 스토리**가 범위다. 16.9·16.10은 새 기능이 아니라 이미 만든 화면(주로 홈 최상단·매물 카드·상세 CTA)을 확정 스파인대로 다시 맞추는 정합성 작업이다.

CLAUDE.md B8: 압축은 산문을 줄이는 것이지 제약을 지우는 게 아니다.)

## Technical Decisions

- **이미지 URL = 공개 버킷 + 고정 URL, 서명 URL 아니다.** ADR-IMG-02가 비공개+서명 방식을 대체했다 — `getPublicUrl(bucket, path)`로 조립(만료 없음). api는 `storage_path`만 반환하고, **URL은 web/app이 각자 조립한다**. (spec-16-10 코드리뷰 3패스에서 복원 — 16.10용 재컴파일이 대체 결정의 출처(ADR-IMG-02)와 "조립 주체" 절을 압축하며 지웠다.)
- **실시간 채팅 = Supabase Realtime "Broadcast from Database".** 토픽 `chat:room:{room_id}`을 트리거·RLS·클라 구독이 동일하게 쓴다. 갭보정 = Broadcast Replay(≤25건/72h) 우선 → 초과분은 `created_at >=` 커서 재조회 + `client_message_id` dedup. Flutter는 `supabase_flutter` Realtime.
- **AI 응답 계약**: `{answer, listings[], route: REJECT|CLARIFY|SQL|HYBRID, narrowed_by?, clarify?: {question, chips}}`. answer는 결정론 생성(**LLM 자유 재작성 금지**). (spec-16-10 코드리뷰 3패스에서 복원 — 재컴파일이 금지 문구를 지워 "결정론 생성"만 남았다. 금지는 산문이 아니라 제약이다.)
- **하단 내비 = `GoRouter StatefulShellRoute` + Material 3 `NavigationBar`.** 4탭: 홈(AI)·찜·채팅·내차팔기, FAB 없음. 프로필=우상단 아바타. "내 차 사기"는 전용 탭이 아니라 홈 하단 스크롤/필터로 도달.
- 디자인 토큰은 웹 단일 출처 미러링(**색·타이포**·카드 레이아웃 B·초록 신뢰뱃지·amber는 가격/CTA 전용·딥 petrol 히어로는 라이트/다크 동일). Pretendard 번들. 구형 WebView는 `backdrop-filter` no-op → 불투명 폴백.
- 역할 어휘: `profiles.role`은 `admin`만 특별 취급, 그 외 전부 `user`. 접근 권한은 이 값이 아니라 소유권(`seller_id`)+RLS.
- 신뢰속성(`accident_status`+CHECK, `is_single_owner`, `is_non_smoker`)은 전부 nullable, NULL="미입력" 제3상태, 항상 "판매자 제공 정보" 면책과 한 몸. 찜은 `wishlists` 단일 저장, 웹·앱 실시간 동기화 없음.
- **16.9 — 홈 최상단**: 상태바·앱바·AI 히어로가 색 경계 없이 하나의 딥 petrol 면. 앱바 좌측 로고 lockup(petrol 배지+"차"+"차장님"), 우측 아바타 하나만(알림 벨 없음 — 걸 곳이 없다). 히어로 배경에 글로우/메시 + 대형 차 실루엣 라인아트(우상단, 옅게, 칩·검색창 비침범). 탐색 진입 박스 제거(히어로 다음이 바로 차종 칩, 히어로 교정과 같은 커밋). 차종 칩 "전체"는 선택 상태(petrol 채움).
- **16.9 — 매물 카드**(`ListingCard.tsx`·`card-final-1.html`이 정본): ① 가격이 카드에서 가장 큰 요소(26/800 상당) + 전용 강조 토큰(`price-emphasis`) — 차량명과 같은 무게면 오답. ② 희소옵션 칩(petrol 아웃라인 3~4개, 넘치면 "외 N")은 0개여도 슬롯을 예약해 카드 높이가 안 흔들린다. ③ 신뢰속성은 사진 위 오버레이가 아니라 사진 바로 아래 전용 행. ④ 순서 = 사진→신뢰속성→차량명→meta→가격→옵션 칩. 카드 크기·열 수는 불변(D5가 4→2→1 열 축소를 규정, 브레이크포인트 1100/640px에서 390px는 1열이 맞다 — **`ai-flow-1.html`의 2열 모바일 프레임은 목업 변형이라 따르지 않는다**). (spec-16-10 코드리뷰 3패스에서 복원 — 재컴파일이 "390px=1열"로 압축하며 2열 목업을 배제한 판단 근거를 지웠다. 그 문장이 없으면 다음 사람이 `ai-flow-1.html`을 보고 2열로 되돌린다.)
- **16.9 — 매물 상세**: 하단 고정 바(판매가+문의하기) 추가 — 지금은 없어 스크롤 중 CTA를 놓친다.
- **16.10 — 히어로 타이포**: 헤드라인이 19px에서 확연히 커지고 2줄("원하는 차를 / **말**로 찾으세요") — 히어로는 스파인이 말하는 "단 하나의 몰입 순간"이라 화면 최대 글자여야 한다. 헤드라인 위 `AI 매물 검색` eyebrow 라벨(반투명 배경+얇은 테두리+점+자간 넓힌 12px = `typography.scale.caption`) 추가. **출시값 = 36px**(`DESIGN.md typography.scale.display`). ⚠️ 이 문단이 예전에 인용하던 "목업 앱 프레임 기준 30~34px"는 **오표기였다** — 그 두 줄(`consistency-1.html:541,568`)은 데스크톱 1280·태블릿 834 **웹** 프레임이고, 진짜 앱 프레임(`.app-hero h2`)은 26px이다. 세 숫자가 서로 다를 때 스스로 우선순위를 주장하는 정본은 스파인 하나뿐이라 36을 택했다(spec-16-10 Design Notes). 검사는 절대값이 아니라 **관계**(헤드라인 > 카드 차량명)로 건다.
- **16.10 — 검색창 테두리(원인 특정 완료)**: `app_theme.dart`의 `InputDecorationTheme`이 `enabledBorder`·`focusedBorder`를 전역 정의하는데 히어로 `TextField`는 `border: InputBorder.none`만 꺼서 못 덮는다(코드 실측). 웹 `HeroSearch.tsx`는 애초 테두리 없이 `rounded-full`+그림자만 쓰므로 웹에 맞춘다. ⚠️ 테마 전역이 아니라 이 위젯에서만 `enabledBorder`/`focusedBorder`도 함께 끈다(테마는 로그인·등록 폼과 공유).
- **16.10 — 차 실루엣**: `Icons.directions_car_filled`(꽉 찬 아이콘)를 목업 라인아트로 교체(사용자 결정 ①안). 구현은 `CustomPainter`/`Path`를 택했다 — 정적 도형 하나뿐이라 `flutter_svg`를 새로 들일 근거가 없다(A2). 같은 도형을 웹 히어로(`HeroSearch.tsx`)에도 인라인 `<svg>`로 넣었다(Non-goal 예외). ⚠️ **배치 규칙은 목업이 프레임별로 다르게 준다 — 하나로 합치지 말 것**: 앱 프레임(`.app-hero .silhouette`) = `right:-8%·top:-14%·width:56%·opacity:.09`(출시값), 웹 프레임(`consistency-1.html:170` 기본 `.silhouette`) = `right:-4%·bottom:-6%·width:min(58%,640px)·opacity:.10`(출시값). 예전에 이 줄이 웹 수치(58%·.10·우하단)를 **앱 항목에 적어 둔 것은 오기였다.** `top` 퍼센트는 컨테이너 **높이** 기준이라 높이가 유동적인 웹 `<section>`에 앱 규칙을 복사하면 무너진다(2패스 브라우저 실측: 390px에서 잉크의 25%만 보임). 도형(path·바퀴) 자체는 두 표면이 같아야 하며 `app/test/hero_silhouette_path_drift_test.dart`가 그 동일성을 실제로 대조한다.
- **16.10 — 모서리 곡률**: 히어로 하단 22 → 14~16(실기기 육안 평가 근거, 목업 수치와는 동일). 카드 radius가 웹 토큰(16)과 일치하는지 확인.
- **16.10 — 대조 기준**: 웹을 폰 폭(390px)으로 앱과 나란히 대조, 남은 편차는 대장에 등재. ⚠️ 비교 대상은 로컬/develop 배포본만 — 운영(`main`)은 반영 보류로 Epic 11 이전 화면이라 부적합.
- **16.9 — 검사 방식(축별 단언 목록)**: 항목마다 위젯 테스트로 시각 축을 **직접** 단언한다 — 앱바·히어로 배경색 연속 여부, 히어로 좌우 여백 0(화면 폭 꽉 참), 히어로 다음 위젯이 차종 칩인지(탐색 박스 0개), 카드 가격 글자 크기 > 차량명 글자 크기, 옵션 칩 슬롯이 옵션 0개일 때도 존재하는지, 신뢰속성이 사진 위젯 뒤(아래)에 오는지. 채택 전 일부러 깨서 red를 확인해야 한다 — 기존 검사가 이 갭을 놓친 이유가 "순서·개수만 봤기 때문"이므로, 새 검사도 같은 함정에 빠지지 않았는지 스스로 증명해야 한다. (spec-16-10 코드리뷰 3패스에서 복원 — 재컴파일이 이 목록을 통째로 지웠다. 아래 "검사 원칙"은 방침이고, 이 목록은 그 방침이 어느 축에 걸리는지를 정한 제약이라 서로 대체되지 않는다.)
- **16.9·16.10 검사 원칙**: 관계형 단언 우선(예: "헤드라인 > 카드 차량명" 크기 비교) — 절대값을 박으면 토큰이 바뀔 때 또 깨진다. 위젯 테스트만으로 시각 축을 닫지 않는다 — 실기기(SM-G991N) 육안 확인 + 스크린샷 증거가 함께 필요하다.

## UX & Interaction Patterns

- 히어로 밴드: 딥 petrol 그라데이션, "원하는 차를 **말**로 찾으세요"(말만 amber) + 알약형 입력 + amber 검색 버튼. 제안 칩 4개는 웹 `HeroSearch.tsx`의 `SUGGESTIONS`가 정본(가성비 좋은 첫차·4천만원대 전기 SUV·주행거리 짧은 무사고 세단·7인승 디젤 패밀리카).
- 차종 칩: 전체·경차·SUV·전기·화물·승합("세단"·"수입"은 DB 값 미대응이라 웹이 이미 대체). 탭하면 해당 필터로 이동.
- "지금 인기"(view_count desc)·"방금 올라온 매물"(created_at desc) 2섹션, 각 4건+전체보기. 앱은 웹의 가로 2단 대신 세로 2섹션.
- Epic 7 잔재 퀵액션(문의 채팅·매물 등록·내 매물 관리)은 히어로/칩/2섹션 신설과 같은 커밋에서 제거 — 먼저 지우면 하단 탭이 화면을 아직 못 여는 동안 등록 경로를 잃는다.
- 매물 카드(레이아웃 B): 사진 5:3 커버("N장" 배지, 없으면 "사진 준비중") → 신뢰속성 행 → 차량명 → meta → 가격(최상위 강조) → 희소옵션 칩. 찜(♡)은 사진 밖 우상단 원형 버튼. 상세는 스와이프 갤러리+"1/N" 카운터+하단 고정 바(가격+문의하기).
- 사진 업로드는 OS 갤러리/카메라 네이티브 피커(크롭·회전·동영상 범위밖), 업로드 전 클라이언트 리사이즈/압축.
- 매물 상세 진입 시 `increment_listing_view` RPC 호출(호출 지점 단일성 검사로 이중 호출 방지) — 완료됨.

## Cross-Story Dependencies

- **실행 순서(정본=sprint-status.yaml)는 문서 번호와 다르다**: 16.1→16.2→16.3→16.4→16.5→16.8→16.7→16.6→16.9→16.10. 16.6은 16.8·16.7이 만드는 화면이 있어야 검증이 성립해 그 다음에 돈다 — 완료 기준은 "배선"이 아니라 실폰에서 실제 동작(상세 열람 전/후 인기 순서 변화, 로그아웃 상태 열람+찜/문의 시점 로그인 유도)까지다. 16.9는 16.1~16.8 결과물을 스파인 기준으로 다시 대조·교정. **16.10은 16.9가 만든 구조(한 면·폭·로고·칩·카드) 위에 타이포·마감을 입히는 단계라 16.9 뒤에만 돈다** — 16.9 없이는 히어로가 아직 카드형이라 앉힐 자리가 없다.
- 16.9는 네 항목(앱바·히어로 연속면, 히어로 배경·탐색박스 제거, 카드 정합, 상세 sticky 바)이 홈 화면 최상단 한 덩어리라 한 스토리로 묶여 있다 — 부분 구현하지 않는다. 16.10도 같은 이유로 네 항목(헤드라인·eyebrow, 검색창 테두리, 차 실루엣, 모서리 곡률)이 한 덩어리다.
- 16.10은 유일하게 웹 코드(`HeroSearch.tsx`)에도 손을 댄다 — 차 실루엣 배경 요소 하나. 에픽 Non-goal("웹 랜딩 재작업")의 명시적 예외라, 이 스토리는 앱·웹 양쪽 커밋을 함께 봐야 한다.
- 16.8은 웹 Epic 11 랜딩과 목업 `app-home-2.html`을 따르는 미러 작업. 16.9는 그 결과물 중 스파인과 어긋난 부분만 교정하며 정보구조를 재설계하지 않는다.
- 16.7은 웹 Story 9.3 업로드 계약(`docs/conventions.md` §10.1)을 그대로 준수.
- 16.1~16.5는 각각 웹 Epic 9(이미지)·10(신뢰속성·찜)·12(실시간 채팅)·13(AI 4분기)이 이미 안정화한 기능을 앱에 옮기는 작업으로, 해당 웹 기능이 선행 조건이다.
