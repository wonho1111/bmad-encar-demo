# Epic 16 Context: Flutter 앱 증분 반영

## Goal

웹이 이미 개편한 디자인 언어(이미지·카드 재설계·신뢰속성·찜·실시간 채팅·4분기 AI)를 Flutter 앱에 미러링한다. 웹 셸(React 컴포넌트)은 그대로 재사용할 수 없어 앱은 별도 위젯으로 새로 구현하되, 색·비율·필드 등 계약은 `docs/conventions.md`를 단일 출처로 공유한다. 웹 기능이 안정화된 뒤 따라가는 것이므로 앱 단계에서 웹의 UX/아키텍처 결정을 다시 논의하지 않고 플랫폼 셸 표현만 번역한다.

## Stories

- Story 16.1: 디자인 토큰 미러 + 하단 4탭 내비
- Story 16.2: 이미지·카드 재설계 (앱)
- Story 16.3: 신뢰속성·찜 (앱)
- Story 16.4: 실시간 채팅 (앱)
- Story 16.5: 4분기 AI 응답·되묻기 칩 (앱)
- Story 16.6: SM-D 통합 시연 검증 (앱)
- Story 16.7: 앱 사진 업로더

## Requirements & Constraints

- 앱 화면은 웹과 동일한 디자인 언어(색 토큰·카드 구성·신뢰속성/옵션 표시·플레이스홀더 규칙)로 개편해야 한다. 웹 이미지·카드 재설계를 앱에도 반영한다.
- 문의 채팅은 폴링이 아니라 실시간(구독)이어야 하며, 메시지가 상대에게 즉시 반영된다. 클라 생성 멱등키로 재전송 중복을 막고, 연결 끊김은 비차단 배너로 알리며, 재연결 시 "마지막 수신 이후" 보정 조회로 갭을 메운다(Realtime은 끊긴 구간을 재생하지 않음).
- 로그인 사용자는 매물을 찜(토글)할 수 있고 찜 목록에 도달할 수 있다.
- 채팅 진입점에 안 읽은 메시지 카운트 배지를 표시하고, 방 목록은 최신 문의 순으로 정렬한다.
- 비로그인 사용자도 매물 열람(목록·상세)은 가능하다. 로그인 게이트는 "행동"에만 건다 — 상태를 바꾸거나 외부 유료 API를 호출하는 것(AI 검색·문의·매물 등록·찜)만 게이트, 단순 열람은 게이트하지 않는다. AI 검색은 호출당 실제 과금이 발생하므로 반드시 신원이 있어야 한다.
- 앱은 웹과 동일 디자인 언어의 별도 구현이며(NFR3), 반응형 웹처럼 하나의 코드베이스를 공유하지 않는다.

## Technical Decisions

- 시각 토큰의 원본은 웹 DESIGN.md(petrol=신뢰/구조, amber=가격·CTA 전용, 신뢰속성=별도 초록 계열)이며 계약 형태로 `docs/conventions.md`에 이월된다. amber CTA의 글자·아이콘은 항상 어두운 잉크(흰색 금지, 라이트/다크 공용 고정). Pretendard 폰트는 웹은 CDN, 앱은 폰트 번들.
- 내비게이션 = `GoRouter StatefulShellRoute`(탭 상태 보존) + Material 3 `NavigationBar`. 하단 4탭: 홈(AI검색)·찜·채팅·내차팔기, FAB 없음. 프로필은 우상단 아바타. AI는 별도 탭이 아니라 홈 최상단 큰 검색부(웹 히어로의 앱 번역판). "내 차 사기"(전체 매물)는 별도 탭 없이 홈 하단 스크롤(인기·최신 발췌)·필터에서 도달.
- backdrop-filter blur는 구형 Flutter WebView에서 no-op이므로 불투명 폴백을 쓴다.
- 이미지 서명 URL: `storage_path`를 서명하는 주체는 web(서버) 또는 app(`supabase_flutter` Storage, 클라측 발급) 뿐이다. api(FastAPI)는 절대 서명하지 않고 `storage_path`만 반환한다(ai_readonly 최소권한 유지). 서명 URL 만료 = 3600초.
- 실시간 채팅 전송 = "Broadcast from Database"(DB 트리거 → `realtime.messages` private 채널) — `chat_messages` 테이블이 소스 오브 트루스이고 정렬은 클라가 `created_at` 기준으로 한다(Broadcast 전달 순서는 보장되지 않음). 토픽 이름 `chat:room:{room_id}`은 web/app/DB 3곳이 동일해야 한다. Flutter는 `supabase_flutter` Realtime 구독으로 웹과 같은 계약을 그대로 쓴다.
- AI 검색 상태(Riverpod)는 웹과 동일한 형태로 미러링한다 — 응답은 구조형/하이브리드/되묻기/거절 4갈래이며, api는 이 라우팅과 되묻기 사유를 이미 구조화해 내려준다.
- `accident_status`는 텍스트+CHECK 제약(네이티브 enum 아님): 무사고=초록 신뢰뱃지, 단순교환/사고=가치중립 중립칩. 셋 다 "판매자 제공 정보" 면책이 붙는다(데모에 객관 검증 인프라가 없어 자기신고로 통일).
- 옵션은 통제 어휘 + 희소도 priority 매핑을 쓴다(`conventions.md` 상수 공유) — 카드는 상위 3~4개만, 상세는 카테고리 전량.
- Client ↔ Supabase 직접 연동(SDK+RLS)이 원칙이다: 이미지 Storage·Realtime 채팅·찜은 FastAPI를 경유하지 않는다. FastAPI는 AI 검색 전용 경계다.

## UX & Interaction Patterns

- 매물 카드(레이아웃 B): 사진 5:3 → 사진 바로 아래 신뢰속성 전용 행(초록 칩+면책) → 차량명 → meta(주행/연료/지역, muted) → 가격 최상위 강조 → 희소옵션 아웃라인 칩. 찜(♡)은 사진 밖 우상단 원형 버튼, "N장" 배지는 사진 위 우하단 다크 글래스 pill.
- 상세 사진 갤러리는 스와이프 + "1/N" 카운터(웹은 좌우 화살표).
- 되묻기 칩은 탭 가능하고 선택 시 petrol 채움 상태가 되며, 자유 타이핑과 병존한다. AI 입력은 최대 500자, 되묻기는 2~3턴 상한.
- 뒤로가기는 기본적으로 진입한 화면으로 복귀(출처 복귀)하되, 삭제·구매완료 전환 같은 파괴적 액션 후에는 안전한 목록으로 명시 이동한다. 앱은 OS 시스템 뒤로가기 제스처로 이 규칙을 구현한다.
- 채팅 메시지 버블: 내 메시지=petrol 채움·우측 정렬, 상대=surface-raised·좌측 정렬. 읽음 표시·타임스탬프·전송중(pending) 반투명 상태를 갖는다.

## Cross-Story Dependencies

- 16.1(토큰·내비 셸)이 기반이며, 16.2~16.5·16.7의 화면이 그 위에서 렌더된다.
- 16.2(이미지 카드)·16.3(신뢰속성·찜)은 웹/앱/api가 락스텝으로 공유하는 ListingCard 계약(이미 Epic 9·10에서 확정)을 그대로 소비한다 — 재정의하지 않는다.
- 16.4(채팅)는 Epic 12에서 구축된 Realtime Broadcast·멱등키·`chat_room_reads` 인프라를 새로 만들지 않고 그대로 구독한다.
- 16.5(AI)는 Epic 13에서 확정된 `/ai/search` 4분기 응답 계약을 그대로 소비한다.
- 16.7(사진 업로더)은 웹 Story 9.3이 확정한 경로 규약·저장 규격·삭제 순서를 그대로 따라야 하며 독자 규격을 새로 정하지 않는다.
- 16.6(SM-D 검증)은 16.1~16.5가 끝난 뒤 실기기에서 돌리는 통합 확인 단계로, 앞 스토리들의 완료를 전제한다.
