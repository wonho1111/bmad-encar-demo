## Intent

**Problem:** 관리자 6화면(대시보드·회원관리·전체매물·매물상세·거래내역·채팅관리)과 아직 아무 에픽도 자기 것으로 가져가지 않은 소비자 화면 10곳이 Story 8.1 디자인 토큰 이전의 원시 `zinc-*` 색상 클래스를 그대로 쓰고 있어, 사용자 화면(이미 리스킨된 카드·상세·찜·계정 화면)과 시각적으로 어긋난다.

**Approach:** `globals.css`(Story 8.1)에 이미 정의된 `@theme` 토큰(표면·잉크·페트롤·앰버·타이포·radius·shadow)과 기존 재사용 컴포넌트(`Button`/`buttonClasses`, `EmptyState`, `ErrorState`)로 대상 16개 화면·컴포넌트 파일의 클래스를 치환한다. `admin-mockups-2.html`은 카드/뱃지/버튼 시각 패턴(색·radius·타이포 위계)의 참고 자료로 쓰되, 사이드바 내비게이션 셸 재구성·신규 KPI 집계 표시 등 구조·기능 변경은 하지 않는다(아래 Never 참조).

## Boundaries & Constraints

**Always:**
- 대상 파일의 `zinc-*`(및 그와 짝지어 쓰인 `red-*`/`blue-*`/`green-*` 등 원시 색상 클래스)를 `globals.css`에 이미 존재하는 토큰 클래스로 치환한다: 표면(`bg-surface-base`/`bg-surface-raised`), 잉크(`text-ink-primary`/`text-ink-secondary`/`text-ink-muted`), 테두리(`border-border-hairline`), 브랜드(`bg-brand-petrol`/`text-brand-petrol`/`bg-brand-petrol/10`), 앰버(`bg-accent-amber`/`text-amber-ink`), 신뢰(`bg-trust-green-bg`/`text-trust-green-ink`), 경고/위험(`bg-warn-amber-bg`/`text-warn-amber-ink`/`text-danger`), radius(`rounded-card`/`rounded-chip`/`rounded-badge`), shadow(`shadow-card dark:shadow-none`), 타이포(`text-display`/`text-section`/`text-card-title`/`text-price`/`text-body`/`text-meta`/`text-caption`). **`globals.css`에 새 hex나 토큰을 추가하지 않는다** — 8.1이 이미 완성한 토큰만 소비한다.
- `web/src/components/ui/Button.tsx`의 `VARIANT_CLASSES`(현재 `zinc-900`/`zinc-300`/`red-300`/`blue-300`)를 토큰 색으로 교체한다. 관리자·소비자 대상 16개 파일 다수가 이 컴포넌트로 버튼을 렌더하므로, 이걸 바꾸지 않으면 "버튼 위계 통일"이 파일별로 아무리 재작성해도 실제 화면에서 이뤄지지 않는다. `primary`/`secondary`/`danger`/`info` 4개 variant의 의미(주 버튼/보조/삭제/정보)는 그대로 유지하고 색만 토큰으로 바꾼다.
- 참고 패턴: 이미 리스킨된 `web/src/app/(user)/account/page.tsx`(가장 단순한 예), `wishlist/page.tsx`의 `BlockedWishTile`, `listings/[id]/page.tsx`가 쓰는 실제 클래스 조합을 그대로 이식한다(비유가 아니라 실물 참고).
- 상태 뱃지(정지됨/활성, 역할 라벨, "나" 표시, 안읽음 카운트 등)는 `admin-mockups-2.html`의 pill 시각 패턴(배경+텍스트 색 쌍, `rounded-badge`)을 토큰으로 재현한다. 새 공용 `Badge`/`Pill` 컴포넌트를 만들지, 화면마다 클래스로 반복할지는 구현 판단에 맡긴다 — 다만 만들 경우 `web/src/components/ui/`에 두고 기존 `EmptyState`/`ErrorState` 패턴(props 최소, 토큰 클래스만 사용)을 따른다.
- 관리자 전체매물·매물상세는 지금처럼 서명 URL 헬퍼(9.2)로 기존 이미지를 렌더한다 — 신규 이미지 기능 추가 없음, sold 매물 열람 유지.
- 기존 관리자 기능의 동작·데이터 쿼리(회원 정지/해제/삭제, 매물/채팅방 삭제, 거래내역 조회, 본인 행 액션 숨김 등)는 한 줄도 바꾸지 않는다 — 바뀌는 것은 클래스뿐이다.
- `(auth)/login`·`(auth)/signup`은 `(auth)/layout.tsx`(DW-547)를 건드리지 않고 페이지 본문 파일만 수정한다.
- 각 대상 파일에서 리스킨 후 `zinc-*` 잔존 수를 grep으로 다시 세어 0임을 확인한다(선언이 아니라 측정으로 닫는다).

**Block If:**
- mockup의 시각 언어(카드/뱃지/버튼/타이포)를 재현하는 데 관리자 데이터 화면(회원관리·전체매물·거래내역·채팅목록)의 `<main><ul><li>` DOM 구조 자체를 바꿔야만 한다고 판단되는 경우 — `web/e2e/core-flows.spec.ts` C6이 `main ul li` 선택자·행 수에 의존한다. 태그 유지가 불가능해 보이면 구현을 멈추고 blocked로 보고한다(선택자를 바꾸는 결정은 이 스토리 범위 밖 — Story 15.2가 반응형 구조를 다룰 때 함께 판단).

**Never:**
- 사이드바 내비게이션 셸(데스크톱 고정 사이드바 + 모바일 슬라이드인)로의 구조 재편은 하지 않는다 — mockup에 있지만 이는 반응형 인터랙션이며 Story 15.2("관리자 반응형")가 "이미 리스킨된 관리자 6화면"을 전제로 소유한다. 현재의 페이지 기반 내비(대시보드 허브의 4개 링크, 각 화면의 뒤로가기)를 그대로 둔다.
- 대시보드·거래내역에 mockup이 보여주는 KPI 집계 카드(총회원 수·판매중 매물 수·이번달 거래액 등)를 새로 만들지 않는다 — 이는 현재 존재하지 않는 신규 쿼리·신규 표시 정보이므로 "신규 기능·운영 배관 추가 금지"(UI-only) 원칙을 넘는다.
- `web/src/components/layout/AppHeader.tsx`는 건드리지 않는다 — 관리자·소비자 전 화면이 공유하는 셸이라 이 스토리가 측정·합의한 16개 대상 파일 밖의 범위까지 블라스트 반경이 넓어진다(별도 판단 필요, 이 스토리 소관 아님).
- 회원관리의 구매자/판매자 필터 정리(FR61)는 여기서 하지 않는다 — Story 15.3이 정책 소유.
- 관리자 판매완료 되돌리기 기능(Story 15.4)이나 그 어떤 신규 관리 기능도 추가하지 않는다.
- 채팅 관리 실시간/폴링 로직, 회원·매물 조회 쿼리 조건을 바꾸지 않는다 — 클래스 치환 외 로직 변경 없음.

1. **`min-w-0 truncate` 패치는 클래스 대칭까지만 확인했고 실제 렌더 폭은 재지 않았다.** 참고 원본(`(user)/listings/[id]`)이 갖고 있는 조합을 관리자 사본이 떨어뜨린 것을 두 파일을 읽어 확인했고, 인텐트 Always가 "그대로 이식"을 요구하므로 이식했다. 다만 "390px에서 실제로 안 넘친다"는 관리자 화면에 뷰포트 매트릭스가 없어(DW-697) 자동으로 확인되지 않는다 — 그 측정은 Story 15.2가 소유한다.
2. **`bg-brand-petrol` + 리터럴 `text-white` 조합이 리포에 아직 한 자리 남아 있다**(DW-698, `OptionPicker.tsx:93`, 다크 2.98:1). 15.1의 대상 파일 밖이라 이번에 고치지 않았고, 이걸 잡는 자동 검사도 리포에 없다.
3. **색 대비 규칙은 여전히 사람이 계산기를 돌려야 한다.** 3회 연속 리뷰 패스가 전부 대비 결함을 찾아냈다는 것은 이 축에 실행되는 검사가 필요하다는 신호다 — DW-698의 fix_sketch에 스캔 형태를 함께 적었고, DW-696의 zinc 스캔과 같은 자리에 넣는 것이 싸다.
4. 라이트 모드 호버 무반응(DW-699)·auth 레이아웃 거짓 주석(DW-700)·DW-697 처방의 공허한 통과 위험(DW-701)은 전부 신규 등재해 trigger를 Story 15.2 또는 해당 파일을 다음에 여는 스토리로 지정했다.
