## 2. 잘된 것

- **구조적 검사로의 전환.** 13-2에서 `status='on_sale'` 부정 우회 차단을 정규식 나열로 두 라운드 연속 뚫린 뒤 `sqlparse` 토큰 검사로 전면 교체했다. "문자열 나열은 적대적 입력을 못 막는다"를 값을 치르고 배웠고, 그 뒤 가드는 18형태 우회 시도를 전부 막았다.
- **비용 드는 검증을 결정론으로 대체한 판단.** 13-9는 라이브 재캡처(57턴 유료 호출) 대신, 변경된 함수 2개를 코드 4버전에 대해 큐리셋 문항으로 직접 호출해 진리표를 비교했다. 돈을 안 쓰고 같은 결론에 도달했다.
- **자기 진단을 스스로 반증한 사례.** DW-656("제일 싼 차가 정렬도 틀렸다")을 등재했다가, 라이브 재현으로 **자기 확인 방법이 틀렸음**(`WHERE id IN (...)`의 반환 순서를 결과 순서로 착각)을 밝히고 취소했다. 팀 합의 4("깬 것이 실제 실행경로인지 확인")가 실제로 작동한 사례다.

## 4. 가장 중요한 발견 — **게이트는 "누군가 넣기로 생각한 것"만 본다**

에픽 종료 후 사용자가 실사용 중 발견한 high 결함 **2건**이 이 에픽의 성격을 규정한다.

| DW | 결함 | 게이트가 왜 못 잡았나 |
|---|---|---|
| **DW-657** | `"아반떼 보여줘"` → **0건**. 모델명을 `=` 정확일치로 찾는데 DB엔 `아반떼 MD`·`아반떼 CN7`뿐 | 큐리셋 62항목 중 **모델명을 단독 조건으로 쓰는 문항이 0개**. `build_golden_sql`에 `model` 키 자체가 없다 |
| **DW-658** | LangSmith 트레이싱이 **로컬·배포 양쪽 모두 한 번도 켜진 적 없음**(Story 13.7 산출물 무효) | 검사(`test_langsmith_env_contract.py`)가 **env 해석 규칙**만 봤다. "트레이스가 실제로 업로드되는가"는 그 파일이 스스로 "안 보는 것"이라 명시해뒀다 |

두 결함 모두 **게이트가 초록인 상태에서** 존재했고, **사람이 10분 써보자 나왔다.**

여기서 3절의 26건과 합쳐 읽으면 교훈이 갈린다. 26건은 *"검사를 잘못 짰다"* 이지만, 이 2건은 *"검사를 아예 안 짠 영역"* 이다. **후자는 검사를 더 정교하게 만들어도 안 잡힌다** — 커버리지의 문제이기 때문이다.

> **모델명 검색은 중고차 서비스에서 가장 흔한 사용 방식인데, 62문항짜리 회귀 스위트가 그걸 한 번도 묻지 않았다.**

## 6. 처분 결정

### 6.1 열린 AI 검색 항목 11건 → **에픽 13에 스토리 2개를 추가한다**

DW-655가 진단한 대로, 이 항목들의 trigger는 **실재하지 않는 스토리**를 가리킨다. Epic 14(계정)·15(관리자)·16(앱)은 `api/app/graph/`를 건드리지 않는다(문서 확인). 그래서 갈 곳을 **만든다.**

**13-10 — 검색 데이터 보강 (재캡처 전 선행)**
- 매물 60~70건 추가(현대>기아>쉐보레>제네시스>르노>BMW>벤츠>아우디 순, 흰/검/회색 세단·SUV/RV 위주)
- 신뢰속성을 전체의 약 절반에 부여(3개 15 / 2개 40 / 1개 25 / 없음 80 배분)
- 새 매물 임베딩 생성 → 로컬 스냅샷 갱신 → 큐리셋 62문항 `count_range` 재계산
- **왜 먼저인가**: 데이터가 바뀌면 정답 건수와 기준선이 전부 무효가 된다. 뒤에 하면 재캡처를 두 번 하게 된다(유료).

**13-11 — SQL 생성 정비 + 채점 축 확장 + 재캡처 1회**
- DW-657 모델명 부분일치(`ILIKE '%…%'`) — **high, 이 스토리의 이유**
- `~같은 X` 를 예시로 취급(조건에서 제외)
- DW-652 최상급 → `LIMIT 1`
- DW-647 `count_range`를 실제 채점 축으로
- DW-646 채점 문항 집합 검사 · DW-648·653 잔여 구멍
- **큐리셋에 모델명 단독 문항 추가** + `build_golden_sql`에 `model_like` 지원 ← 4절의 사각지대를 닫는다
- 라이브 재캡처 1회로 4축 비하락 확인

**닫는 것**: DW-658·659는 **오늘 이미 해소**(커밋 `9988976`) — 평소 실행 경로에서 트레이싱이 켜지고 `.logs/api.log`에 판단 근거가 남는 것을 라이브로 확인했고, 배포 서버도 사용자가 env를 넣고 재배포해 트레이스 업로드를 실측 확인했다. **DW-656은 invalid**, **DW-645는 실측으로 범위 축소 후 low**.

### 6.2 `max_review_cycles` 2 → **3으로 올린다**

에픽 12 회고가 스스로 정한 상향 조건이 충족됐다(9/9 소진). 3절이 보여주듯 **마지막 리뷰 패스까지 새 문제가 나왔고**, 특히 13-8·13-9는 4패스째에 high를 찾았다. 2회로는 부족하다는 것이 두 에픽 연속 실측으로 확인됐다.

### 6.3 `#168`(DW-468) — **에픽 13이 트리거였는데 안 됐다. Epic 15로 재지정**

Epic 11 회고가 `#168`(E2E CI 배선 + **CI red 알림 자동화**)의 트리거를 *"Epic 13 게이트 정비"* 로 못박았는데, 에픽 13 9개 스토리 어디에도 이걸 처리한 흔적이 없다. **트리거가 실재하는 에픽을 가리켰는데도 그냥 지나갔다** — 5절의 DW-655와는 다른 유형의 누락이다(가리킬 곳이 없어서가 아니라, 가리켰는데 아무도 안 봐서).

Epic 15(관리자 UI)는 web 작업이라 E2E·CI와 같은 축이다. 거기로 재지정하고, **인수조건 체크박스로 심는다**(B5 규칙 — 회고 문서에만 두면 이행되지 않는다).

### 6.4 나머지

| 안건 | 결정 |
|---|---|
| 웹 칩 UI(DW-587·597·600) | **Epic 15로**. 서버는 칩을 정확히 보내는데 웹이 안 그린다. 관리자 UI 작업과 같은 web 워크스트림이다 |
| `ai-ab-test-queryset.json` 이름 | **바꾸지 않는다.** A/B 목적은 끝났지만 파일명이 스크립트·문서·CI에 박혀 있어 개명 비용 > 이득. 대신 `_meta.purpose`에 "현재 용도 = RAG 회귀 게이트"를 적는다 |
| 앱 조회수 | **Epic 16으로**(앱 증분 에픽에 자연스럽게 속한다) |
| `epic-13` 상태 | **backlog → in-progress** (아래 참조 — 회고 중 사용자 지적으로 정정) |

**⚠️ `epic-13`을 `done`으로 닫지 않는다 — 회고 진행 중 사용자가 지적한 모순이다.**
이 문서 초안은 `epic-13: backlog → done`을 제안했는데, 같은 문서가 **에픽 13에 스토리 2개(13-10·13-11)를 새로 만든다**고 결정하고 있다. 끝났다고 선언한 에픽에 일감을 추가하는 것은 앞뒤가 안 맞고, 무엇보다 **DW 항목들의 trigger가 다시 "닫힌 에픽 안의 스토리"를 가리키게 되어 DW-655가 진단한 바로 그 병이 세 번째로 재발한다.**

그래서 순서를 이렇게 고정한다:
```
epic-13: in-progress   ← 지금
   ↓  13-10 (데이터 보강) → 13-11 (SQL 정비 + 재캡처)
epic-13: done          ← 13-11 완료 시
```
**회고는 다시 돌리지 않는다.** 이 회고가 그 두 스토리를 만들어낸 주체이므로 재실행할 안건이 없다 — 13-11이 끝나면 이 문서의 액션 이행 여부만 확인하고 에픽을 닫는다. (회고가 에픽 종료보다 먼저 오는 것 자체는 문제가 아니다. 회고의 목적이 "남은 일을 찾아 갈 곳을 만드는 것"이었고 실제로 그렇게 됐다.)

Epic 14(계정 역할 통합)는 `profiles.role`·회원가입·판매 게이트만 건드리고 **AI 검색 코드와 무관**하다(문서 확인). 즉 13-10·13-11과 **병렬로 진행해도 충돌하지 않는다.**

착수 시 함께 볼 것:
- **DW-459** — 구매자·관리자에게도 "내 차 팔기" 메뉴가 뜨고 눌러도 말없이 홈으로 튕긴다. 트리거가 이미 "Epic 14가 role을 스레딩할 때"로 걸려 있다. 14.3에서 (a)role 전달 (b)메뉴 제거 (c)안내 화면 중 결정.
- 마이그레이션 번호는 **0027**(문서의 `0013`은 무효 — 문서 자신이 경고를 달아뒀다).
- 14.1은 CHECK **완화(ALTER)** 라 순수 "더하기"는 아니다. 기존 행을 지우거나 바꾸지는 않으므로 B3 위반은 아니지만, 착수 시 명시적으로 짚을 것.
