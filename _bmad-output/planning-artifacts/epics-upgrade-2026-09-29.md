# Epic 18: 운영 서비스 고도화 — 소셜 로그인·회원·이메일·결제 (웹)

작성 2026-09-29. 범위는 **웹(Next.js)만** — Flutter 앱은 이 에픽에서 건드리지 않는다(사용자 결정 09-29).
순서는 사용자 지정: 소셜 로그인 → 회원 고도화 + 이메일 → PG 결제. 알림은 제외, 기술부채는 맨 뒤.

공통 제약
- develop에서 작업, main 병합은 사용자 승인 후(CLAUDE.md B3).
- DB 변경은 마이그레이션으로 **더하기만**(B3).
- 외부 계정(카카오 개발자센터·Resend·도메인·토스페이먼츠)은 사용자 명의로 사용자가 만든다. 키는 환경변수로만 받고 저장소에 커밋하지 않는다.
- 결제 금액 등 중요한 값은 클라이언트가 보낸 값을 믿지 않고 서버·DB가 직접 구한다(B9).
- 각 스토리는 브라우저 E2E로 직접 확인한 뒤 완료(B4).

## Story 18.1: 카카오 로그인
로그인 화면의 카카오 버튼으로 가입·로그인한다. 첫 카카오 사용자도 프로필이 정상 생성된다. 같은 이메일의 기존 계정이 카카오로 들어올 때의 동작을 실측해 기록한다.

## Story 18.2: 메일 발송 기반 (Resend + 도메인 인증)
Supabase Auth 메일을 Resend SMTP로 보낸다. 도메인 SPF·DKIM 인증을 통과하고, 지메일·네이버 받은편지함 도착을 확인한다.

## Story 18.3: 가입 이메일 인증
가입 시 인증 메일 → 링크 클릭 전에는 로그인 불가(한국어 안내) → 재발송 가능. 기존 회원 영향 없음.
완료 조건 추가(18.2 이월): 한국어 메일 양식을 운영에서 발송해 **지메일 받은편지함 도착**을 확인한다(영어 기본 양식은 3회 모두 스팸함). 미인증 이메일 계정에 같은 이메일 카카오 로그인이 들어올 때의 동작 실측(18.1 이월). 카카오 가입 이메일로 일반 가입 시 안내 문구 개선(18.1 이월).

## Story 18.4: 비밀번호 재설정
"비밀번호 찾기" → 메일 링크 → 새 비밀번호 설정 → 로그인. 재설정 메일도 한국어 양식 + 지메일 받은편지함 확인(18.2 이월). "아이디 찾기"가 필요 없는 근거(이메일이 곧 아이디)를 정리한다.

## Story 18.5: 토스 결제 — 매물 상단 노출 구매 (테스트 키)
판매자가 본인 매물의 상단 노출 기간을 결제한다. 결제창 → 서버 승인(금액은 서버가 DB에서 구함) → 상단 노출 반영. 결제 기록 테이블은 마이그레이션으로 추가.

## Story 18.6: 결제 취소·환불·웹훅
판매자 취소 → 토스 환불 → 상단 노출 해제. 웹훅이 중복 도착해도 한 번만 처리된다.

## Story 18.7: 기술부채 선별
장부(deferred-work.md) 열린 항목 중 18.1~18.6과 부딪히는 것만 추려 우선순위를 제안한다.
